# Rainbow 与 DQN 改进组合

这篇用于前几篇读完后的串联，不要求一次实现全部模块。

## 这些名字并非互相替代的版本号

不同改进发生在不同位置，因此可以组合。原版 Rainbow 将六种改进接到一起，并做消融实验研究各部分的贡献：[Rainbow 原论文](https://arxiv.org/html/1710.02298v1)。

| 改进 | 改训练流程的哪里 | 仍然需要什么 |
| --- | --- | --- |
| Double | 下一动作的选择与估值 | 正确下一观察与目标网络 |
| Dueling | Q 网络的输出结构 | 明确动作维和聚合规则 |
| PER | 回放抽样与损失权重 | 可靠经验、概率与优先级写回 |
| n-step | 目标使用的连续奖励段 | 每个环境独立的时间与结束边界 |
| C51 | 回报表示与分布损失 | 投影、概率归一化、回报范围 |
| NoisyNet | 网络参数中的探索 | 噪声抽样与评测约定 |

**Rainbow-lite** 通常是对简化组合的非正式称呼，没有所有实现都遵守的统一配方。本页用 `Double + Dueling + PER + n-step` 作四项组合的例子，它没有包含原版 Rainbow 的全部六项。

`QR-DQN + Dueling + PER + n-step` 则是以分位数回报表示为核心的另一种组合，不能直接叫原版 Rainbow。是否再使用 Double、怎样定义分位数损失和 PER 优先级，需要明确写出。

## 用一组数串起四项组合

这里只演示上面的四项组合，保持每个动作一个 Q 值，便于把目标、预测和损失逐步手算出来。

经验中最早的实际动作是 2。连续三次奖励为 `[0, 0, 2]`，γ=0.9，未终止；末状态的 online 输出 `[4, 5, 3]`，target 输出 `[7, 2, 4]`。

| 顺序 | 计算 | 得到什么 |
| --- | --- | --- |
| n-step 汇总 | `0 + 0.9×0 + 0.9²×2` | 奖励和 1.62；累计折扣 0.729 |
| Double 选下一动作 | online 的 `[4,5,3]` 取最大位置 | 下一动作 1 |
| Double 估值 | target 在动作 1 处取值 | 2 |
| 构造固定目标 | `1.62 + 0.729×2` | 3.078 |
| Dueling 计算旧预测 | 旧观察的 V=2、A=`[1,-1,3]`，减平均后合成 | Q=`[2,0,4]`；实际动作 2 的预测为 4 |
| 计算误差 | `3.078 - 4` | TD 误差 -0.922 |
| PER 加权 | 若本次该样本归一化权重为 0.5 | 加权平方损失贡献 `0.5×0.922²=0.425042` |

最后还要与本批其他样本按约定归约，再反传更新在线网络。若优先级采用 `abs(TD误差)+0.001`，这条样本写回值为 0.923；这表示预测差距，不是在奖励或惩罚游戏事件。

样本是按更新前缓存的优先级抽到的；抽到后才计算本轮误差，供以后抽样使用，不能倒过来声称先知道所有当前误差再抽样。

```text
交互与多步队列 → 回放池 → PER 抽样
                    ↓
旧观察 → Dueling在线网络 → 实际动作Q ──────┐
末状态 → online选动作 → target估值 → 多步目标
                    ↓                    ↓
                固定目标 ───────────→ 加权loss
                                         ↓
                         梯度 → 在线参数 → 后续目标同步
```

旧实际动作 2 与末状态选出的动作 1 承担不同职责。四项组合没有改变“环境提供奖励、在线预测接收梯度、目标计算保持固定”这条主线。

## 原版 Rainbow 还有需要读准的连接

C51 与 Dueling 组合时，是对每个回报位置组织价值和动作差别，再形成各动作的分布。Double 的下一动作按期望 Q 选，然后读取该动作的整份目标分布。n-step 改的是分布目标的奖励平移与累计折扣。

原论文的回报分布版本用分布 KL 损失安排 PER 优先级，并非始终使用标量 `|TD误差|`。因此“把六个名字写在配置里”不足以说明已经复现 Rainbow；每个模块之间的数据和损失接口都要讲清。

## 以后怎样做有结论的实作

可以先验证 Double 的目标，再独立验证 n-step、Dueling 和 PER 的机制，最后组合。对游戏做实验时一次改一个研究因素，保持任务、奖励、动作规则、训练预算和模型选择规约可比较。

组合有效后，再用“拿掉某个模块”的消融判断它是否有贡献。容量变化、每次更新的计算量和实际交互量要记录，不能只比较相同墙钟时间下的一张奖励曲线。

组合更多算法不保证收敛。观察缺失、奖励目标偏差、重置错误、训练覆盖不足都可能让复杂算法失败。读完这些概念也不表示当前游戏已启用它们或已经通关。
