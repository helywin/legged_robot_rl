# 自动求导与梯度

损失用一个数字评价当前预测。对这里的标量损失调用 `backward()`，会沿已经记录的计算路径求导，并把梯度累加到相连、需要梯度的叶子参数 `.grad` 中。没有连接到损失的参数，不会因为出现在同一个模型里就自动得到梯度。

```text
参数 → 预测 → 损失
              ↓ backward
参数.grad ← 梯度
```

梯度的符号表示增大参数时损失变化的方向，绝对值表示当前局部的敏感程度。

## 从一个新建的 loss，怎样找到旧参数

设输入 x = 2，权重 w = 0.5，偏置 b = 0.1，目标 y = 1.5。目标是本次固定的对照数值，不参与求导。模型先按 `q = w*x + b` 预测，再算 `L = (q-y)²`：

```text
q = 0.5 × 2 + 0.1 = 1.1
L = (1.1 - 1.5)² = 0.16

损失对预测的梯度：dL/dq = 2 × (1.1 - 1.5) = -0.8
预测对权重的梯度：dq/dw = x = 2
预测对偏置的梯度：dq/db = 1

接起来：dL/dw = -0.8 × 2 = -1.6
        dL/db = -0.8 × 1 = -0.8
```

为什么要相乘？w 增加一小点会让 q 增加约两倍那么多；q 的这点变化再影响 L。梯度把这两段影响串起来。

如果 w、b 是需要梯度的 PyTorch 参数，乘法、加法、平方这些运算会在前向时记录依赖。`loss` 虽然是刚产生的对象，却携带通向 q，再通向原来 w、b 的关系。反向计算后，参数仍是 0.5 和 0.1；清空旧梯度后做这一次反传，`.grad` 分别为 -1.6 和 -0.8。下一步才交给 [[概念/优化器与参数更新]]。

## 有数值，不代表还有求导路径

把 q 用 `.item()` 取成普通 Python 数字，再用它另造一个张量，不会恢复到原来 w、b 的计算关系。`detach()` 也会切断相应求导路径，但它不是独立存储副本，不能据此认为随意原地改值不会影响原张量。

变量名叫不叫 `loss` 不影响求导；真正起作用的是计算依赖。梯度的正负只描述当前位置附近的变化方向，不保证任意大的更新都让损失下降。规则可查 [PyTorch 自动求导说明](https://docs.pytorch.org/docs/stable/notes/autograd.html)。

## 职责边界

- `backward()` 计算梯度，不直接修改参数；
- 梯度不是奖励，也不是新的参数值；
- 参数更新还需要学习率和明确的更新步骤或优化器；
- 多次反向计算的累积与清空见 [[概念/梯度累积与清零]]。
