# 标准环境接口

标准接口把任务差异封装在环境内部：`reset()` 开始新一局，`step(action)` 推进一步并返回观察、奖励和结束信息。

Gymnasium 风格的返回约定为：

```python
observation, info = env.reset()
next_observation, reward, terminated, truncated, info = env.step(action)
```

`step()` 中的新观察、奖励和标记必须来自同一次动作的后果。`info` 可携带诊断数据，但不自动成为策略输入。

## 停止的原因决定怎样看未来

| 情况 | 是否结束这一段回合 | 是否保留下一状态的价值估计 |
| --- | --- | --- |
| 到达任务定义的终点或失败状态，`terminated=True` | 是 | 否，只用本步奖励 |
| 持续任务被外部时限截断，只有 `truncated=True` | 是 | 是，用截断发生时的最后观察 |
| 采样器暂时收够一批数据，任务仍在进行 | 只是本批暂停 | 是；不要伪造环境终止标记 |

不能仅凭“到了时间上限”判断一定为截断。如果任务本身就是“在 60 秒内得分”，60 秒属于任务定义的一部分，到时可以是真正终止；为了完整描述这类状态，观察还需包含剩余时间。这个区别依据 [Gymnasium 时间限制说明](https://gymnasium.farama.org/tutorials/gymnasium_basics/handling_time_limits/)。

## 最后一帧和重置第一帧，不能混成一条经验

例如最后一个动作让小车到达位置 2.3，随后重置到 0。回放记录中的 `next_observation` 应是 2.3 对应的那一刻，不是 0。否则会教给网络一个虚构后果：“这个动作能把我瞬移回中心”。

使用自动重置封装或并行环境时，最后观察的提供方式取决于版本、封装和自动重置模式；应核对接口实际返回值，不能盲目照抄某个旧版 `info` 键名。

环境重置通常恢复场景并清空本局观察历史；DQN 参数、优化器状态和回放经验跨局保留。若保存的是可变数组，还需保存当时数值，不能只留下之后会被改写的对象引用，见 [[概念/环境交互到经验记录]]。

当前 `FrozenLakeEnv` 已采用 Gymnasium 风格的核心返回结构：`reset()` 返回观察和 `info`，`step()` 返回新观察、奖励、`terminated`、`truncated` 和 `info`。通用循环应根据两个结束标志退出，而不依赖自定义的 `env.done` 属性。

第 037 课记录的 Gymnasium 1.3.0 `CartPole-v1` 提供了当时的接口证据：第一次 `step()` 返回四项新观察、奖励 `1.0`、两个结束标志和 `info`。当时固定种子的 100 回合随机策略全部以 `terminated=True` 结束，没有到达 500 步的时间截断。这不是对当前所有任务的结束方式作保证。

第 059 课进一步把 `reset()` 的动作前观察与同一次 `step()` 的动作、奖励、新观察和结束标记组成一条经验，并由学习者练习确认相邻经验的观察首尾相接、终止后不再继续 `step()`。
