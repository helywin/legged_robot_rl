# 游戏内部状态与策略接口

游戏内部为了运行而保存的数据，不等于外部Python程序已经可以读取的数据。策略观察是我们明确交给网络的输入；动作编号也只是约定，必须由环境适配代码翻译为真实控制。

## 一组数字串起完整含义

假设一个宽200像素的教学场景，飞机横坐标50，敌机横坐标80。若选择结构化观察，可以输入归一化的两个坐标 `[50/200, 80/200] = [0.25, 0.40]`。除以宽度是换成相对位置尺度，不是训练出来的参数。这两个坐标不足以描述完整游戏，只用于讲接口。

数字从哪里来才是关键：从截图开始时，得到的是像素，不是坐标。要么另有程序识别物体并计算位置，要么让网络直接处理图像；不能假装截图自然变成两个坐标。若修改游戏提供状态读取接口，则可能直接拿坐标，但必须确认来源、时刻和坐标系。

假设人为定义三个动作：0保持、1左移、2右移，网络本次输出 `[1.2, 0.4, 2.0]`。最大值位于编号2，所以选右移。网络只产生Q值，外层选择索引，再由适配层映射成输入事件。2不是位移2像素，也不是操作系统的键码。实际位移由游戏控制逻辑、动作持续时间和边界决定。

最小算术演示，不是真实游戏读取或控制：

```python
observation = [50 / 200, 80 / 200]
q_values = [1.2, 0.4, 2.0]  # 假定的网络输出
action_index = q_values.index(max(q_values))
print(observation, action_index)
```

预期输出 `[0.25, 0.4] 2`。第一行只缩放已给定坐标；第二行没有调用模型；第三行先找最大值再找它的索引（并列时取第一个）；第四行展示约定结果，不发送按键。本例不发生参数更新。

## 两种接入路径，不能混称

| 路径 | 观察怎么来 | 主要待解决问题 |
|---|---|---|
| 窗口截图与输入事件 | 采集像素，再选图像输入或识别后的数字 | 焦点、采样时刻、输入保持、奖励与结束识别 |
| 游戏源码提供接口 | 在游戏内部导出约定字段或画面 | 接口实现、编译、推进时序、维护成本 |

源码接口也能只给策略图像；结构化观察也可能由图像识别产生。“数据怎么获取”和“网络吃什么”不是同一个选择。072课当时未实施源码接入；后续已按用户授权开展，最新边界见文末。

## 训练器可以知道策略没看到的事

例如游戏提供精确损命事件供环境计算奖励，而策略输入仍只用画面。损命信息没有自动成为网络输入。必须分别记录策略观察字段和用于奖励、终止判断的字段；否则容易误以为网络知道一切。

对于真实机器人，同样不能因为仿真内部有某个量，就认为部署时策略也能取得它。本课不展开机器人实现。

## 072—073阶段证据

实际行为入口：[[073-real-game-input-baseline]]。先用人工输入确认控制规则，再验证程序输入；两者不是同一层证据。

2026-09-07学习者报告073人工操作通过：无输入不动、保持按键期间移动、释放停止，支持四向与斜移。程序需要维护完整按键状态：右上切换为右时释放上键，切换为保持位置时释放所有方向键。八方向加不移动可构成候选9种移动动作，但开火组合、斜向速度与自动输入仍未验证。

2026-09-07本机静态检查：`command -v chromium-bsu`为 `/usr/bin/chromium-bsu`；`pacman -Qi chromium-bsu`报告包版本 `0.9.16.1-4`。

阅读 `/usr/share/man/man6/chromium-bsu.6.gz`：手册列出鼠标、方向键或手柄控制，左键或空格等开火，P或Pause暂停，并提示设备支持依赖编译选项。因此键盘控制是待实测候选，不是本课已验证的输入注入能力。

阅读 `/usr/share/doc/chromium-bsu/info.html`：说明敌机漏过屏幕底部会损失战机。这证明奖励事件设计不能只考虑被子弹击中，不证明已有可机读事件接口。

本轮没有启动游戏、截图、发送输入、读取实时坐标或训练网络；未找到接口不等于证明不存在接口。下一步应先验证最小的真实动作与画面反馈，再选接入实现，不能直接拼一个虚构的 `env.step()`。

## 后续源码接口实证（2026-09-07）

用户已确认Python客户端能打印状态。进一步实现的同步GUI原型见 [[experiments/2026-09-07-chromium-synchronous-step/README]]：动作由进程协议直接交给游戏控制逻辑，不再经桌面按键注入，因此输入法不参与这一条链。

只读snapshot回答“此刻是什么状态”，同步step回答“把这个动作完整执行指定步数后是什么状态”。snapshot不会使同步游戏推进；IDLE动作则仍推进游戏，只释放控制输入。源码表明松键时控制累积量乘0.7逐步衰减，与肉眼看起来马上停止并不矛盾。

目前有程序右移/斜移、持续开火、精确步数和等待冻结的原生证据。每tick仍绘图，尚无完整渲染拆分、seed/reset、奖励或稳定对象ID，也没有把这些原始字段确定为网络最终输入。阶段C仅部分完成，不把同步GUI原型称为完整训练环境。
