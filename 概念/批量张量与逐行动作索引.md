# 批量张量与逐行动作索引

批量张量把多条结构相同的经验沿第 0 维堆在一起。对于离散动作 Q 网络：

```text
observations.shape = (经验数量, 每条观察的特征数)
q_values.shape     = (经验数量, 动作数量)
```

每条经验记录的实际动作可能不同，因此必须在每一行使用自己的动作列号，得到形状为 `(经验数量,)` 的 `selected_q_values`。

去掉逐行索引产生的单元素动作维时，应指定 `squeeze(1)`。不指定维度的 `squeeze()` 会在批量大小为 1 时连批量维一起删除，使输出从 `(1,)` 意外变成标量 `()`。

## 为什么普通索引不够

对二维 Q 值张量使用 `q_values[executed_actions]` 会索引第 0 维，也就是选择经验行；它不会自动理解为“每一行分别选择一个动作列”。逐行选列需要同时保留行与列的对应关系，可使用沿动作维的 `gather`。

## 两条经验，各取自己的动作列

假设网络输出和回放中的动作如下，动作编号从 0 开始：

```text
Q = [[1, 4, 2],       actions = [2, 0]
     [7, 3, 5]]

第 0 行取第 2 列 → 2
第 1 行取第 0 列 → 7
selected_q = [2, 7]
```

第一行当前最大 Q 是 4，但这条经验实际执行动作 2，所以应训练值 2。第二行恰好执行了贪心动作，不能由此把整批统一改成取最大值。

后续 target 的第 0、1 项必须分别对应这两条经验；既要按行配对，也要检查形状，避免 [[概念/PyTorch张量]] 中 `(B,1)` 与 `(B,)` 意外广播的错误。

## 计算图边界

- 动作编号是整数索引，不需要梯度；
- 选出的 Q 值仍连接到在线网络参数；
- 只完成前向和索引不会修改网络参数；
- 后续 loss 可以同时使用这一批 selected Q 值完成一次批量反向更新。
