# 环境交互到经验记录

一条环境转移记录把同一个交互步的前因和后果保存在一起：动作前观察、实际动作、动作后奖励、动作后观察，以及两个结束标记。

```text
当前 observation
→ 执行 action
→ env.step(action)
→ reward、next_observation、terminated、truncated
→ 组成一条 transition
```

## 时间关系

若本步的旧观察记作 $o_t$，执行动作后得到 $o_{t+1}$：

$$
T_t=(o_t,a_t,r_{t+1},o_{t+1},terminated,truncated)
$$

保存完成后才执行 `observation = next_observation`。**同一个环境、同一个回合、未经打乱的连续记录**中，前一条的 `next_observation` 应等于后一条的 `observation`。跨回合重置、不同并行环境或已经随机抽样的回放列表，不应强求相邻条目首尾相接。

## 先保存前因，再接力下一步

假设位置依次是 2 → 3 → 4，两步都向右。应保存两条记录：“2、右、对应奖励、3”和“3、右、对应奖励、4”。如果第一条尚未保存就把旧观察覆盖成 3，可能记成“3、右、奖励、3”，动作前因就丢了。

还要注意可变对象：若环境重复使用同一块观察数组，而回放只保存引用，后续 `step()` 改数组时，过去的记录也会跟着变。保存经验应留住当时数值，例如使用不可变值或按实际数据结构复制。`tuple` 外壳里面若仍装着可变数组，也不能只凭外壳不可变就认为安全。

## 职责边界

- `reset()` 提供本局第一项当前观察；
- 策略提供实际执行动作；
- `step()` 根据动作推进环境并产生后果；
- `VectorTransition` 只保存数据，不计算 Q 值；
- 回放缓冲区只保存和抽样经验，不替环境产生经验；
- 只有后续 loss、`backward()` 和 optimizer 才会修改网络参数。
