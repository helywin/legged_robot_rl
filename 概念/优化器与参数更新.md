# 优化器与参数更新

优化器负责读取模型参数的梯度，并按照学习率修改参数。`backward()` 与优化器的职责不同：

```text
loss.backward()  → 计算梯度，参数不变
optimizer.step() → 使用梯度，按优化器规则尝试更新参数
```

最简单的 SGD 更新可以理解为：沿着梯度相反的方向移动一小步。学习率控制这一步有多大。

## 一次更新的顺序

```text
观察 → 模型预测 → 损失 → backward() → 参数.grad
                                      ↓
                               optimizer.step()
                                      ↓
                                  新参数
```

## optimizer 没有绑定 loss

创建优化器时传入的是 `model.parameters()`：

```python
optimizer = torch.optim.SGD(model.parameters(), lr=0.1)
```

优化器保存这些参数对象的引用，而不是保存 `loss`。另一边，前向计算使用同一批参数产生预测和损失，PyTorch 的计算图由此知道损失依赖哪些参数。

```text
参数 ──前向计算──→ prediction ──→ loss
 ↑                                  │
 │                                  │ backward()
 └──────── optimizer.step() ←── 参数.grad
```

`loss.backward()` 沿计算图把结果写入叶子参数的 `.grad`。`optimizer.step()` 遍历自己保存的参数引用，读取每个 `.grad`，再按照学习率修改参数。二者不直接认识，对接点只有同一个参数对象及其 `.grad`。

不带动量、权重衰减等附加项的 SGD，核心行为可用下面的伪代码理解：

```python
for parameter in optimizer管理的参数:
    if parameter.grad is not None:
        parameter -= learning_rate * parameter.grad
```

## 接着上一页的数字完成更新

沿用 [[概念/自动求导与梯度]]：x = 2，w = 0.5，b = 0.1，目标 1.5；预测 1.1，平方损失 0.16；本轮梯度为 w.grad = -1.6、b.grad = -0.8。

设普通 SGD 学习率为 0.1，按“旧参数减去学习率乘梯度”计算：

```text
新 w = 0.5 - 0.1 × (-1.6) = 0.66
新 b = 0.1 - 0.1 × (-0.8) = 0.18
```

两项参数一起更新后，用新参数重新前向：q = 0.66 × 2 + 0.18 = 1.5，新损失为 0。旧 `loss` 对象保存的本次计算结果仍为 0.16；它不会因为参数后来改变就自动重算。

这组数字恰好一步拟合这个点，不代表所有样本或 Adam 都有同样结果。若从同样的初值出发，把学习率换成 0.3，则 w = 0.98、b = 0.34，预测变成 2.3，损失变成 0.64，反而比 0.16 更大：方向合理，步子仍可能迈过头。

## 什么需要跨轮保留

模型保存参数；带动量的优化器和 Adam 等还会保存历史统计。每轮重新创建这类优化器，会丢失它们的更新历史。仅加载网络权重后重新创建优化器，也不等于恢复原训练现场。

`step()` 不会替你清除旧 `.grad`。零梯度也不总能推出参数不变，例如已有动量或权重衰减仍可能产生更新；上面的手算明确限定为普通 SGD。

## 职责边界

- 优化器不负责产生预测或定义损失；
- `step()` 使用已经存在的梯度，不替代 `backward()`；
- 多轮训练前清空旧梯度见 [[概念/梯度累积与清零]]；
- 一次损失下降不代表 DQN 已经训练成功。
- `loss` 不需要注册到 optimizer；把 optimizer 理解为“损失容器”是不正确的。
