# 优化器与参数更新

优化器负责读取模型参数的梯度，并按照学习率修改参数。`backward()` 与优化器的职责不同：

```text
loss.backward()  → 计算梯度，参数不变
optimizer.step() → 使用梯度，参数改变
```

最简单的 SGD 更新可以理解为：沿着梯度相反的方向移动一小步。学习率控制这一步有多大。

## 一次更新的顺序

```text
观察 → 模型预测 → 损失 → backward() → 参数.grad
                                      ↓
                               optimizer.step()
                                      ↓
                                  新参数
```

## optimizer 没有绑定 loss

创建优化器时传入的是 `model.parameters()`：

```python
optimizer = torch.optim.SGD(model.parameters(), lr=0.1)
```

优化器保存这些参数对象的引用，而不是保存 `loss`。另一边，前向计算使用同一批参数产生预测和损失，PyTorch 的计算图由此知道损失依赖哪些参数。

```text
参数 ──前向计算──→ prediction ──→ loss
 ↑                                  │
 │                                  │ backward()
 └──────── optimizer.step() ←── 参数.grad
```

`loss.backward()` 沿计算图把结果写入叶子参数的 `.grad`。`optimizer.step()` 遍历自己保存的参数引用，读取每个 `.grad`，再按照学习率修改参数。二者不直接认识，对接点只有同一个参数对象及其 `.grad`。

SGD 的核心行为可近似理解为：

```python
for parameter in optimizer管理的参数:
    if parameter.grad is not None:
        parameter -= learning_rate * parameter.grad
```

## 职责边界

- 优化器不负责产生预测或定义损失；
- `step()` 使用已经存在的梯度，不替代 `backward()`；
- 本节点只记录一次更新，多轮训练前清空旧梯度属于后续课程；
- 一次损失下降不代表 DQN 已经训练成功。
- `loss` 不需要注册到 optimizer；把 optimizer 理解为“损失容器”是不正确的。
