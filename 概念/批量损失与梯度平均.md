# 批量损失与梯度平均

一批经验中的每条经验先用自己的 selected Q 和 target 计算逐条损失，再对这些损失取平均，形成一个标量 loss。

```text
每条经验的预测与 target
→ 每条经验自己的平方损失
→ mean 得到标量 loss
→ backward 汇总平均梯度
→ optimizer 对整批只更新一次
```

## 为什么经验不会因平均而消失

平均 loss 的计算图仍分别连接每条经验。`backward()` 会把每条路径的梯度除以批量大小后相加到共享参数 `.grad`，因此每条经验都保留自己的方向和大小贡献。

## 为什么通常不用求和

对同一批数据，求和损失的梯度等于平均损失梯度乘以批量条数。平均能去掉这个由条数直接带来的倍率；换一批数据仍可能改变梯度方向和波动，不能据此断言所有批量大小都可用相同超参数。

## 必须先平方，再平均

假设预测为 [2, 0]，目标为 [1, 1]，预测减目标得到 [1, -1]：

```text
正确的平均平方损失 = (1² + (-1)²) / 2 = 1
先平均误差再平方   = ((1 + (-1)) / 2)² = 0
```

后者把一高一低的错误直接抵消，会错误地报告没有损失。

但**不同样本的参数梯度相互抵消**可以是合理结果。例如一个模型只能对两条样本都输出同一个参数 w，目标分别为 -1、1。当 w = 0 时，两条损失都是 1，梯度分别为 2、-2，平均梯度为 0。在这个受限模型下，平均损失 `((w+1)²+(w-1)²)/2 = w²+1` 的最小值确实是 1。此时未必是 `backward()` 坏了，也可能是输入信息或模型表达能力不足。

整批一次更新也不等于逐条更新多次：逐条更新后参数已经变化，后面样本的梯度会在新参数上计算。只有在同一组参数上分别算梯度，再按权重合并，才对应平均损失的梯度。

## 平均改善不等于逐条改善

不同经验的梯度会在共享参数上相加。它们可能方向一致，也可能互相冲突。optimizer 直接优化的是整批平均 loss，因此更新后平均值可以下降，同时某一条经验的 loss 暂时上升。

[[064-mean-loss-and-single-sample-tradeoff|第 064 课]]用两条固定经验展示：A 的 loss 从 `0.0289` 升到约 `0.0650`，B 从 `1.0000` 降到约 `0.6950`，平均值仍从 `0.51445` 降到约 `0.38001`。
