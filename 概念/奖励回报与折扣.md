# 奖励、回报与折扣

这一页只分清三个量：**奖励**是一步的反馈，**回报**把后续奖励合在一起，**折扣**规定越远的奖励在当前计算中占多少权重。阅读本页不代表完成了新课程。

## 一段经历，为什么会有不同的数字

假设小车连续三步收到奖励 [1, 0, 2]，第三步之后任务真正结束。环境每一步只给当时的奖励；经历完成后，我们可以回头算整段回报。

不打折时，从第一步开始的回报为 1 + 0 + 2 = 3。

若奖励每延后一步就乘一次 0.9，那么第一步收到的 1 不打折，第二步的 0 乘一次 0.9，第三步的 2 乘两次：

```text
第一步开始的折扣回报 = 1 + 0.9 × 0 + 0.9² × 2 = 2.62
第二步开始的折扣回报 = 0 + 0.9 × 2 = 1.8
第三步开始的折扣回报 = 2
```

这也解释了递推写法为什么成立：2.62 = 当前奖励 1 + 0.9 × 后面整段回报 1.8。

记当前步为 t，本步奖励为 r_t，折扣为 γ，回报为 G_t，刚才的关系就是：

$$
G_t = r_t + \gamma G_{t+1}
$$

本仓库不同材料可能把“执行动作后得到的奖励”写成 r_t 或 r_{t+1}；先看它对应哪次转移，不要只凭下标判断错了一步。

## 未来没有发生时，怎样计算

完整回报要等未来奖励实际出现。一步 Q-learning 没有等到整段结束，而是用下一状态的 Q 估计代替未知的后续回报。这让信息能逐步向前传播，也把估计误差带进了目标。

因此，已经观察到的回报、当前估计的 Q 值、用来更新 Q 的目标，可能是三个不同的数。见 [[概念/Q-learning更新]] 和 [[概念/DQN目标Q值]]。

## γ 改的是评价时间，不是修改速度

对同一段 [1, 0, 2]：

| γ | 从第一步算的回报 | 含义 |
| --- | --- | --- |
| 0 | 1 | 只看这一步 |
| 0.5 | 1.5 | 两步后的 2 只剩 0.5 的权重贡献 |
| 0.9 | 2.62 | 更重视后续收益 |
| 1 | 3 | 这个有限回合中不打折 |

这不会修改环境发出的 [1, 0, 2]，只改变算法怎样评价它们。学习率则控制一次参数更新的幅度。

γ = 1 在本例有限回合中没有问题；无限持续、每步都有正奖励的任务则可能累加到无穷，不能把这个例子直接照搬过去。

## “一步”多长也属于定义

0.9 通常是每次决策的折扣，不是每秒固定打九折。若修改动作保持时间，同样的 γ 对应的实际时间偏好会改变。要保持相同物理时间尺度，需一起检查区间奖励的计算和折扣，见 [[概念/动作保持与观察时间对齐]]。

上面的数字是教学假设，未更改任何任务奖励或训练配置。原始定义可查 [Spinning Up 的奖励与回报说明](https://spinningup.openai.com/en/latest/spinningup/rl_intro.html#reward-and-return)。
