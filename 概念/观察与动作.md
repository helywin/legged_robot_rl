# 观察与动作

**观察**是策略当前能够得到的信息，**动作**是策略交给环境的决定。

观察不一定等于环境的完整真实状态。走格子时它可以只是位置编号；游戏中可能是画面和自身状态；机器人中可能是关节、机身姿态和指令。

## 同一个位置，为什么可能需要相反的动作

假设小车要停在中心：

| 环境中的真实情况 | 只给位置时，策略看到什么 | 更有用的控制信息 |
| --- | --- | --- |
| 在中心，正在快速向右滑 | 位置 0 | 应考虑向左制动 |
| 在中心，正在快速向左滑 | 位置 0 | 应考虑向右制动 |

只看位置的确定性策略收到完全相同的输入，就只能给出相同输出。增加网络层数不能凭空恢复被删除的速度。可以直接提供速度，或用带时间间隔的历史位置估计运动；两种办法的噪声和适用条件不同，见 [[概念/单帧观察与运动信息]]。

## “程序知道”不等于“策略看到了”

环境可以知道子弹碰撞、游戏分数和终止原因，用这些信息计算奖励、记录日志；只有实际送入策略的字段才属于策略观察。不能因为某字段出现在日志中，就认为网络用到了它。

同样，观察有多少项和动作有多少个是两回事。四个小车状态可以对应“向左、向右”两个离散动作；机器人若输出若干连续数值，需要另行定义每个数的单位、顺序、缩放和限幅。

## 职责边界

- 环境负责产生观察并执行动作；
- 策略只读取观察并输出动作；
- 动作经过仿真执行器或控制器后才会变成物理运动。

“期望前进速度”可能是给策略的任务指令，“各关节目标角度偏移”可能是策略动作，“电机力矩”则可能由后续控制器计算。应先查接口定义，不能把三者都当成同一种动作。一个数值例子见 [[概念/策略动作到关节控制]]。
