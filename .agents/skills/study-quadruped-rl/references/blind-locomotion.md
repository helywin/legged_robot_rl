# 盲走与楼梯任务检查表

## “盲走”的操作性定义

将“盲走”定义为：actor（真正输出动作的策略网络）不接收相机、深度图、激光雷达、射线高度图、局部高程图、地形类别或未来落脚点等外部地形信息。

通常可作为本体感知输入的量包括：

- IMU 可估计的机身角速度和重力方向；
- 关节位置和关节速度；
- 足端接触信息（仅在真机确实可获得时）；
- 用户速度指令；
- 上一时刻动作。

逐项质疑仿真观测在真机上如何得到。仿真中的准确机身线速度和直接接触力不一定能在真机上以相同质量获得。若依赖状态估计器，要单独记录其来源、延迟、噪声和漂移。

critic 可以在训练时使用地形高度等 privileged information，但 actor 不可以。必须检查 actor/critic 的观测分组，而不是只看统一的 `observations` 名称。

## Isaac Lab 审计方法

从任务注册 ID 追到环境配置，并搜索以下线索：

```bash
rg -n "height_scan|ray|camera|depth|lidar|observations|PolicyCfg|CriticCfg" \
  <isaac-lab-checkout>/source/isaaclab_tasks
```

再确认：

- `height_scan` 是否属于 actor/policy 观测；
- actor 与 critic 是否共用同一个观测组；
- 移除外感知后，网络输入维度和归一化是否随之更新；
- 回放脚本是否加载了与新观测维度匹配的 checkpoint；
- 地形扫描器即使仍在 scene 中，是否真的没有进入 actor。

“传感器还存在但不进入 actor”与“完全删除传感器”是两个不同实验。优先做最小改动证明观测契约，再决定是否删除无用传感器以节省性能。

## 楼梯能力验收

不要用一段成功视频作为唯一验收。至少记录：

- 上楼和下楼分别的成功率；
- 完成规定阶数所需时间；
- 跌倒率、机身撞台阶率和非足端碰撞率；
- 不同踏步高度、踏面深度、摩擦和接近角下的结果；
- 不同随机种子和未参与调参的测试地形结果；
- 关节动作变化率、力矩或能耗代理指标。

先让课程从容易台阶逐步增加难度。课程难度、奖励设计和域随机化不要在同一次实验里同时大改。

## 从仿真到真机的边界

仿真盲走成功只证明策略在当前模型和扰动范围内工作。真机前还要验证：

- 机器人型号、质量、关节方向、零位和限位与模型一致；
- 策略频率、PD 增益、动作缩放和真机底层接口一致；
- 观测估计、噪声、延迟、丢包和时钟行为被建模；
- 电机温度、功率、关节速度和力矩有独立安全限制；
- 吊架/保护绳、软垫、低台阶、急停和旁站人员已经就绪。
