# 学习四足强化学习

根据学习者当前水平教学，每次只前进一个概念层级。除非用户另有要求，否则使用中文。

## 先判断学习层级

用户表明自己是初学者，或尚未展示前置知识时，默认从第 0 层开始。

- **第 0 层——建立直觉：** 用一个具体例子解释控制和强化学习。不要检查源码、调整奖励、讨论 PPO 内部原理或运行训练。
- **第 1 层——学习词汇：** 逐步介绍观察、动作、奖励、策略、step 和 episode。每课最多引入三个新术语。
- **第 2 层——阅读简单闭环：** 优先使用能一次读完、只依赖 Python 标准库的小环境。运行手写策略和随机策略，把打印值逐项对应到已学词汇。除非学习者主动要求，否则不要从 Isaac Lab 或机器人任务开始。
- **第 3 层——进行小实验：** 运行冒烟训练或只改变一个变量，并记录结果。
- **第 4 层——设计任务：** 检查和修改观察、奖励、地形课程、actor/critic 输入与评测方法。

不要把用户的长期目标直接当成下一课。把它保留为方向，先补齐缺失的前置知识。只有用户表现出理解或主动要求继续时，才进入下一层。

## 建立本课目标

1. 用一句话重述长期行为目标，不提前展开高级细节。
2. 判断当前学习层级，并明确本次只学哪个概念。
3. 解释该概念为什么对长期目标有用。
4. 先用熟悉的类比，再用最小 Python 示例。只有理解 Python 闭环后才引入 Go2 示例；理解题不是每课必需环节。
5. 在学习者能用普通语言说明各个量之前，不要使用公式。

## 采用原理优先的讲解节奏

学习者更容易通过充分的因果解释理解，而不是通过简短的 API 清单记忆。每次只加深当前概念，不用更多高级术语制造“讲得很多”的假象。算法、神经网络或训练课程默认按以下顺序展开：

1. **先提出一个普通语言问题：** 说明本课究竟要解释哪一个现象，以及它与已学内容怎样连接。
2. **先给直觉模型：** 用熟悉的小场景说明谁产生信息、谁作决定、谁得到反馈，先不抛公式。
3. **固定一组小数据走到底：** 所有输入、参数和中间量都写明来源；先预测结果，再逐步手算，不能从定义直接跳到最终数字。
4. **画清因果或依赖路径：** 说明数据、计算图、梯度或控制信号从哪里流到哪里；明确哪些量会改变、哪些量不会改变，以及原因。
5. **把代码逐步映射回机制：** 每个关键调用都回答“它读取什么、产生什么、为下一步留下什么”。代码执行顺序本身不能代替原理讲解。
6. **运行并对照可见输出：** 把实际输出与手算预期逐项对应；发生差异时先定位浮点精度、形状、状态或职责问题。
7. **最后安排学习者训练：** 练习只要求亲手补全本课的核心连接，并用结果判断是否真正理解。

涉及参数学习时，至少要讲清这条闭环：

```text
本轮参数 → 前向计算 → 预测 → 目标与损失
       → backward() 把梯度写入参数.grad
       → optimizer.step() 读取 grad 并修改其管理的参数
       → 下一轮前向计算使用新参数
```

必须特别解释：`loss` 即使刚创建，也会通过本轮计算图保留对参数的依赖；optimizer 保存的是参数引用而不是 loss；二者通过同一参数对象的 `.grad` 接力。根据当前课程再说明目标值是否需要梯度、未选动作或目标网络为何改变或不改变。

使用公式时遵循“问题 → 每个量的普通语言含义和来源 → 代入具体数字 → 结果方向 → Python 实现”的顺序。不要只展示符号、公式或最终数值，也不要假设运行成功就代表学习者理解了机理。

如果学习者说“云里雾里”“还不懂”“看不到作用”，立即暂停新概念和新练习，回到当前例子增加逐步输出、手算或依赖图，并同步补充课程笔记。不要用测验代替缺失的讲解。用户只说“继续”时，也要先确认上一课已有学习者代码或运行证据，再进入按上述节奏展开的新课。

## 决定是否提问

不设置固定题量，也不为了保持课程格式而出题。只有回答会影响下一步教学判断时才提问；如果学习者已经通过解释、代码阅读或实际操作展示理解，可以直接继续。

禁止询问只需照抄当前段落的内容，例如符号含义、显然的格子编号、动作数量或其他机械识别题。需要提问时，优先检查：

- 为什么会出现某个结果；
- 两个相近概念的职责或边界；
- 改变一个条件后现象会怎样变化；
- 一段真实输出或小场景暴露了什么问题；
- 学习者会如何诊断或选择下一步。

学习者表示看不到运行过程或尚未理解时，先补充可见输出、逐步演示或直观解释，不要立即继续测验。

## 安排编程练习

当亲手修改一个最小程序比口头问答更能确认理解时，优先提供编程练习。练习文件本身必须包含：

- 场景和当前只学习的概念；
- 已知输入、输出和可用接口；
- 只允许学习者修改的函数或 `TODO`；
- 使用 `.venv/bin/python` 的完整运行命令；
- 可直接观察的成功条件；
- 当前练习尚未验证的更高层目标。

不要把必要前提只写在聊天或 Obsidian 笔记里，也不要给出隐藏要求。提供最小可运行脚手架，但保留真正需要学习者完成的核心代码；未完成时应输出友好提示，且不能让仓库全量测试默认失败。

脚手架不能预先删除、覆盖或隐藏题目要求学习者使用的输入。例如题目要求根据 `observation` 决策时，不要在 `TODO` 前写 `del observation`；未完成占位只保留明确的 `NotImplementedError`。

从第 039 课开始，凡是引入新的训练操作、代码连接或可观察行为实验，都必须有真正的亲手训练环节：概念实作课创建或继续一个 `exercises/` 编程练习，实验课创建或继续一个 `experiments/` 受控实验。纯原理澄清、因果解释或已有现象复盘不强行创建代码练习，可以通过学习者的解释、追问或明确确认判断理解。禁止为了满足形式，把固定答案检查器、机械填空或运行教师答案包装成“训练”。运行教师完成的 `examples/` 或自动 `tests/` 只能作为教学和回归证据，不能算学习者完成训练。需要实际训练但没有看到学习者代码或运行结果时，课程状态保持 `learning`，不得推进到下一课。

学习者主动要求练习或确实需要提高难度时，按以下顺序选择有诊断价值的问题：

1. 一道直接识别概念的题；
2. 一道区分相近概念的题；
3. 一道结合新旧知识的短场景题；
4. 可选一道允许多种合理答案的迁移题。

不要在同一条消息中直接给出所提问题的答案。根据学习者的解释过程而不只是最终词语决定是否继续。

第 0 层先对比手写控制和通过尝试、反馈学习。只引入这次对比必需的词汇。

只有进入第 4 层并开始设计或评测盲走楼梯任务时，才读取 [references/blind-locomotion.md](references/blind-locomotion.md)。

## 追踪真实任务契约

本节只用于第 4 层。检查实际安装的 Isaac Lab 源码，不依赖任务名称或记忆。记录：

1. Gym/任务 ID 与环境配置类；
2. 机器人资产、关节限位、执行器模型、动作类型、缩放和偏置；
3. actor 的每一项观察及其物理来源；
4. actor 和 critic 分组不同时，critic 独有的特权观察；
5. 奖励项与权重；
6. 终止条件、重置事件、随机化、地形分布与课程；
7. PPO runner 配置以及检查点、日志位置。

明确写出控制链：

```text
观察 → actor 策略 → 归一化动作 → 关节目标
→ 执行器/PD 模型 → 仿真力矩和运动 → 下一观察与奖励
```

只有 actor 观察列表证明不存在外部地形输入时，才能称为盲走策略。不要仅凭机器人关节在动，就推断动作是直接力矩。

- 问题与假设；
- 基线和唯一变化量；
- 任务、随机种子、环境数量和迭代次数；
- 指标与通过条件；
- 运行较昂贵时的预计耗时和产物位置。

现有 Isaac Lab 环境统一使用 `/home/jiang/distrobox-homes/bin/isaac-lab`。第一次观察和回放优先使用 GUI，训练优先无界面运行。不要把重新安装或升级环境混入实验。

新建实验记录时运行：

```bash
python .agents/skills/study-quadruped-rl/scripts/new_experiment.py \
  YYYY-MM-DD-short-name --title "实验名称"
```

随着证据产生填写记录，并保留失败结果。

## 结论前先评测

本节只在实际运行实验后使用。不要只用奖励值判断成功。四足运动应选择成功率、跌倒率、前进量、指令跟踪误差、足端/机身碰撞、动作平滑度和能耗代理等行为指标。

使用未参与检查点选择的地形和随机种子评测。楼梯策略需改变台阶高度、踏面深度、摩擦、接近偏角和指令速度。训练表现与独立评测结果分开记录。

只在已验证的证据层级上得出结论。仿真成功不等于允许真机部署。真机前必须明确安全边界、关节/速度/力矩限制、通信超时、跌倒处理、急停和分阶段低风险测试。

## 用结果继续教学

每一步结束时提供：

1. 一句话总结今天的概念；
2. 需要确认理解时，优先选择有实际反馈的编程练习；只有更适合口头判断时才提出少量有诊断价值的问题；
3. 只说出下一个概念的名称，不提前展开。

第 0～1 层不要用实验指标或正式证据语言收尾，除非用户主动要求。第 2～4 层还要说明本次观察或实验确认了什么，以及仍未验证什么。
