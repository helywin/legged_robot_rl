# Chromium B.S.U.方向输入与释放的GUI验证

## 问题

方向键能否控制本机游戏中的飞机？松开后是否停止由该键引起的移动？先建立人工输入基线，随后才能判断自动输入失败在哪一层。

## 假设

根据已安装手册，预期右键使飞机向右、左键使飞机向左。松开后的行为未知，需要实测，不能预先认定没有惯性或鼠标干扰。

## 环境与配置

- 状态：等待学习者GUI操作结果；仅文档静态核对完成。
- 任务：本机 Chromium B.S.U.；非Isaac Lab。
- 窗口：640×480，关闭声音，1个窗口；保留现有难度设置，不改游戏配置文件。
- 桌面：本次检查为Wayland，DISPLAY=:0；存在xdotool不代表自动控制已经可用。
- 训练迭代数：0；不是模型训练，是学习者亲手进行的接口行为实验。
- 随机种子：尚无已验证的种子设置接口；本实验不比较分数、存活时间或精确位移。
- 基线：活跃游戏中，飞机远离横向边界，没有移动输入时的行为。
- 唯一变化量：横向输入状态，无输入→右键→无输入→左键→无输入。保持其他输入、窗口、设置不变。
- 预计用时：2～3分钟；没有长运行或参数更新。

## 命令

```bash
/usr/bin/chromium-bsu --window --vidmode 1 --noaudio
```

## 观察与指标

### 学习者操作

1. 若已有游戏窗口，使用已有窗口，别重复启动。否则执行上面的命令，从菜单人工进入新游戏。
2. 确认处于实际游玩画面，不是菜单或暂停。不要用连续按Enter试探控制：手册把双按Enter列为自毁输入。
3. 游戏获得焦点后不要移动鼠标，不按开火键，让飞机远离左右边缘；短暂不按方向键，观察它是否自行横移。
4. 按住右方向键约0.2秒后松开，观察按住期间和松开之后的运动。只需轻短按，不要把飞机推到边缘。
5. 仍在同一生命、未撞边界且游戏正常推进时，同样短按左方向键，再观察松开之后的行为。重复一轮确认不是偶然现象。
6. 若死亡、复活或碰到边界，这段观察标记为无效，从新的可观察状态重做；不要据此判断按键失效。若无输入时飞机自行移动，先记录，不强行判定方向控制通过。
7. 若方向键完全无效，停止加长按压，报告游戏是否有焦点、是否正在游玩，以及飞机是否跟随鼠标。不要同时改鼠标、难度和键位。

约0.2秒仅是手动短按指导，不是实测时间，更不等于固定数量的游戏更新。鼠标控制可能干扰键盘，应以实际现象为准。本实验仅判断方向和释放行为。
