# 真实游戏动作与17项观察对照

## 问题与假设

学习者完成的离线编码能否直接读取真实游戏快照？固定动作执行5个tick，向右组的世界x和观察第0项应同步增加；共同初始状态下的IDLE组不施加方向输入。编码本身不应推进状态。第一步目标是数据连接，不是生存或通关训练。

## 环境、配置与唯一变化量

- 当前子模块原生同步第一关GUI，默认每步绘图；每次1个环境、0次网络更新。
- 共同初始化1个IDLE tick，再执行5个单tick动作；每步观看等待0.7秒，末尾3秒。
- 唯一人为改变项：`--action idle`与`--action right`；无开火。
- K=2，位置尺度10、控制尺度20、子弹位移尺度1，资源尺度-500/500/9。
- 尚无公共seed/reset：各次启动是不同进程，随机初始条件不能保证一致，只核对自身动作和编码关系，不对比分数或完整敌机轨迹。
- 依赖既有本地原生构建及仓库.venv，不安装或升级环境。

## 完整命令与亲手操作

仓库根目录依次运行，分别看窗口和终端：

```bash
.venv/bin/python experiments/2026-09-09-chromium-observation-step/run.py --action idle
.venv/bin/python experiments/2026-09-09-chromium-observation-step/run.py --action right
```

每次预计十几秒以内，含游戏启动。脚本自动关闭自己创建的进程。比较RIGHT组飞机是否右移，world_xy第一项与player_obs第一项是否一起改变；再看IDLE组。不要把IDLE视为整个游戏暂停。

成功条件：单次执行完整5步；每步观察17项；观察第0项为同一快照x/10；编码不会让同步世界自行推进；动作的实际影响与观看结果对应。提前终止、断言或启动失败时保留输出，不继续解释为通过。
