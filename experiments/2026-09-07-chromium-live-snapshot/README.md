# 真实游戏画面与Python状态快照对照

## 问题

手动操作真实游戏时，Python读取的位置、生命和敌机数量能否对应画面？只做状态观察，不训练网络、不构造DQN经验。

## 假设

右移时世界坐标x增大，上移时y增大；出现敌机后enemies数量可能增加。数据来自游戏内部对象，不是截图识别。菜单初始位置已由教师读取为(0,-3,25)。

## 环境与配置

- 证据级别：教师已完成构建、菜单状态通信和进程清理；学习者活动游戏对照待完成。
- 任务：独立子模块Chromium B.S.U. for RL的只读实时客户端，非Isaac Lab。
- 并行环境数：1个GUI；不需要手动先开游戏，脚本自己启动。
- 训练迭代数：0。
- 随机种子：当前不支持；不比较得分优劣或精确轨迹。
- 基线：无方向输入的短时画面与Python坐标。
- 只改变的变量：先只改变横向输入，再单独观察纵向输入；保持其他设置和鼠标不变。

## 产物

- 实时结果打印在终端，可复制一小段到本记录或聊天。
- 无检查点、视频或训练指标。每个进程配置保存在临时目录，退出后清理；失败会显示日志尾部。

## 观察与指标

1. 从脚本打开的菜单进入游戏，先观察终端的mode是否变为game。
2. 在远离边界时短按右键，观察画面右移与终端x变化；再单独短按上键观察y。避免同时移动鼠标。
3. 看一眼敌机出现与enemies计数；若采样间隔内敌机出现又消失，计数不必反映每个事件。
4. 关闭窗口或在终端Ctrl+C。报告坐标是否对应、关闭是否残留游戏，以及异常输出。

脚本每0.5秒读取一次，不暂停游戏，不保证读到所有中间变化。生命字段是内部lives_counter，不把0直接解释成整局结束。成功条件是位置变化与画面方向一致且退出能清理进程，不要求高分或固定数值。

学习者结果（2026-09-07）：用户确认“测试了可以打印状态了”。状态读取实测确认；尚无逐字段、坐标方向和退出残留的详细反馈，不补写不存在的证据。

## 结论

教师已确认初始菜单快照和通信错误处理；活动游戏画面对照尚不能标为通过。
