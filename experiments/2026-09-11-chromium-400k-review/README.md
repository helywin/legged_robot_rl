## 逐局诊断

固定检查30001/30002/30003（未按成绩挑选），逐步结果存`runs/400k-policy-diagnostic.json`。边缘定义abs(x)>=9.5或abs(y)>=7，仅是位置描述。

- 30001：180决策、5000分，173步结束在边缘附近。
- 30002：172决策、2500分，165步结束在边缘附近。
- 30003：174决策、5000分，172步结束在边缘附近。

三局均会切换动作，并非旧4000模型那样全程固定动作17；弹药库存一直为零。基础枪在HeroAircraft::shootGun中无条件发射基础子弹，库存为零不等于不能开火。弹药拾取增强火力；不能把补弹说成开火必要条件。

30002第117步：飞机在(10,7.5)，生命从3降到2，分数却从0升到2500，任务奖励+25；此前y=-11.844的弹药0道具同一步消失。结合PowerUps.cpp中道具y<-12给2500分的规则，强烈支持这是漏接得分；快照未提供精确得分来源事件，因此仍不把所有同类得分逐笔确认为同一分支。

EnemyFleet.cpp:328—335明确规定敌机越过y=-14会调用loseLife。因此待在角落即使避开碰撞，也可能因漏敌机而损命。当前奖励只读总分，没有直接表达漏机或损命代价。

另有价值估计偏高现象：30002第117步最大Q约183，而这条贪心轨迹从该步到结束的实际未折扣奖励仅25。这不是单独的代码错误证明，也不能排除价值估计偏差、部分观察和训练稳定性等其他因素。

## 结论与下一步

40万更新没有解决这组开局中的生存问题；当前不应继续单纯加预算，也没有证据支持删除子弹速度能解决问题。优先纠正奖励目标与拦截/通关目标的差距：补充可验证的漏机、损命、击杀、拾取和漏接事件，使任务能够区分收益来源；设计新版奖励后保持观察、网络及其余训练配置进行对照。

不直接用贴边惩罚强迫移动，避免把症状当目标。尚未修改游戏计分、奖励或启动新任务训练，保留现有失败模型。事件接口与新版奖励属于后续实质修改，需按课程解释和验证。
