# 真实子弹等待与单步推进对照

## 问题与假设

081早期没有敌方子弹，本实验验证非空观察槽。相同动作和尺度下，同一ID子弹在不推进时保持原样，在推进1tick并存活时按velocity_per_tick移动；观察中的位置与运动来自同一颗子弹。

## 环境、配置、唯一变化量

1个原生同步第一关GUI，默认逐步绘图，0次网络更新。保持IDLE，不开火。最多600tick寻找有效样本，普通等待阶段每步0.02秒，候选子弹出现后现实等待1秒作为零推进对照，再执行1tick。成功后停留3秒并关闭自己拥有的游戏进程。唯一对照变量是推进0或1tick；原始和下一状态按稳定ID对应，不按槽位身份对应。

K=2，沿用17项观察尺度：位置10、控制20、子弹位移1、资源-500/500/9。复用现有.venv和子模块构建；没有公共seed，坐标不要求与教师一致。初始化与生成子弹依当前游戏随机状态，通常十几秒内完成，未找到样本或提前终止时明确报告未完成。

## 完整命令与学习者操作

```bash
.venv/bin/python experiments/2026-09-09-chromium-bullet-step/run.py
```

观察before的ID、世界坐标、每tick位移和对应五项槽。检查现实等待时same_snapshot=True，随后推进1tick的predicted_xy和actual_xy近似相同。选择输出中的y，亲手用before的y加per_tick_y，与actual_y对照一次；报告你这次的数值即可。不需要改游戏或训练代码。

如ID消失，脚本不把它当作击中证明，也不与另一颗子弹比较，而是继续寻找有效存活对。达到上限、提前终止或异常时保留输出，不记为通过。

## 产物、指标与教师结果

产物为终端输出，无检查点、数据集或视频。指标：17项有效性、五项槽位与对应子弹字段一致、等待快照不变、同ID一步位置误差。容许float32舍入，位置比较rel_tol=1e-6/abs_tol=1e-5。

2026-09-09教师原生结果：tick35找到ID2、type0，飞机(0,-3)，子弹xy约(6.667673588,7.063679218)，每tick位移(0,-0.200000003)。第一槽约(0.666767359,1.006367922,0,-0.200000003,1)。等待1秒快照一致；推进1步预测y=6.863679215、实际y=6.863679409，误差约1.94e-7，检查通过，正常退出。未截图独立审阅画面，不声称所有子弹类型或策略验证完成。
