# Chromium首轮DQN训练

问题：学习者从零实现的Task、回放、DQN更新和训练循环，能否在真实游戏跨局执行并产生有效权重？
假设：先保证循环和参数更新成立；不假设500次更新能优于随机。
环境：Chromium同步第一关，seeded-reset-v3，X11/GL，CPU单线程，跳过逐步绘图（仍依赖显示）。唯一方案：首版task-v1，无对照因素；本次不是单因素改进实验。

学习者实际运行命令（仓库根目录）：

```bash
.venv/bin/python exercises/chromium_dqn/train.py --run
```


产物路径：`exercises/chromium_dqn/runs/train-06fbbc3a5a1c4ff78afc7ffabb1586c1/`，含config.json、steps.jsonl、summary.json与policy.pt。产物受忽略规则管理，不提交模型。当前Python实现是未提交工作区版本；后续冻结评测版本时需补齐提交标识。

用户运行结果及教师文件核对一致：755次决策，3局结束，500次更新，累计任务奖励80.5，最后一批loss=0.010129079222679138，参数变化为true，总耗时1.8899736000457779秒。755行日志，500行发生更新；自然终止位置为第228、413、632次决策，没有250步外部截断。日志未记录自然终止的细分原因，不能仅据这份日志将其说成死亡或过关。第4局执行123次决策后达到训练更新预算。

为何755：第256条经验存入后开始第1次更新，直到755，共755-256+1=500次。奖励80.5是多个回合累计的任务奖励，不是某一局游戏得分，也不是独立评测成绩；末批loss不代表整个训练趋势或策略能力。

教师已使用torch.load(weights_only=True)加载本地检查点，以当前QNetwork严格恢复参数；参数均有限，诊断前向输出[1,18]且有限。`play.py --check`进一步通过任务版本、输入输出维数和tick规格校验。这些属于加载/结构验证，不是GUI策略回放。

结论：学习者已完成真实短训练闭环及保存权重。失败/局限：未证明优于随机，单关及短回合设置不能代表完整游戏，推理检查点不含完整续训状态。
