# 事件奖励与旧分差奖励的受控对照

## 问题与假设

40万更新后模型仍贴边。原始分数混入漏接道具收益，不能直接代表拦截/通关行为。假设：保持110维观察、网络和训练配置，改用击毁/拾取/损命/过关事件奖励，可能减少无效贴边。该假设需要实验，不能只凭奖励看起来合理就宣布成功。

## 冻结规则

- task-v3-events，观察与task-v2-powerups均110维、18动作、5tick/动作、每局250决策。
- 奖励 = 击毁数量 + 0.2×拾取数量 - 5×实际损命数量 + 20×本步过关。
- 漏机已损命，不再重复罚；漏接道具不直接奖励，不惩罚位置，不加存活时间奖励。
- 击毁基准1；损命代价相当于5次击毁；拾取辅助反馈仅为击毁的1/5；过关相当于20次击毁。这些是待验证的相对偏好，不是推导出的最优系数。
- 游戏原始分数和物理规则完全不变。累计事件来自原生episode_events，同一局快照作差，不能被同一步加命抵消。击毁含子弹、碰撞和连锁爆炸引起的非静默销毁，不是精确子弹击杀归因。
- 8环境、CPU、headless，网络/回放种子7、探索11、游戏31；容量10000、批量32、预填256、gamma0.99、SGD0.001、epsilon0.2、目标同步100。
- 第一轮4000更新验证连接，预先说明后再进行40000更新正式小对照；各自只与同预算8环境旧模型比较，不比较两种奖励的累计数值。期间未调系数。
- 模型/随机各20局，种子30001..30020，贪心冻结，原始分数、模拟时间、终止原因与事件均记录。该种子组已用于开发诊断，不作为最终盲测集。

## 结果

4000更新：新/旧平均击毁0.70/0.35，平均存活19.488/18.963秒，死亡19/20与20/20。这只是有限初步现象。

40000更新的20局结果：

| 指标 | 旧分差奖励 | 新事件奖励 |
| --- | ---: | ---: |
| 平均原始得分 | 5875 | 5663.75 |
| 平均模拟存活秒数 | 18.524 | 18.595 |
| 平均击毁 | 0 | 0.15 |
| 平均漏机 | 4.85 | 4.90 |
| 平均实际损命 | 5.15 | 5.05 |
| 平均拾取 | 0 | 0.35 |
| 平均漏接道具得分 | 5875 | 5625 |
| 死亡 / 截断 / 过关 | 20 / 0 / 0 | 20 / 0 / 0 |

同组随机：平均击毁0.85、拾取0.95、存活19.185秒、20局死亡。新奖励尚未优于随机或显著改善生存，不能称为解决贴角落。旧模型平均分全部由漏接贡献，已由原生来源计数确认。

新40000训练中，正奖励189条、负奖励1024条、零奖励39042条。正奖励只占约0.47%，且包含拾取，不全是击毁。这提供了检查有效经验和价值学习的线索，但不单独证明探索不足是唯一原因。负累计奖励-5069.2由既定损命惩罚产生，不是接口报错。

## 验证与边界

C++构建通过；原生16项、Python侧9项测试通过。真实16个种子观察到了所有新增事件字段变化，验证累计单调、reset清零、读取不推进。原生旧/新程序去掉新增事件字段后，三个种子的全部快照与步进结果相同。实际损命三条源码路径均计数；原生随机测试未触发RL动作未暴露的自毁路径。

人工奖励检查验证同时加命/损命不被净值掩盖、漏接得分不进入v3、事件差分、过关仅奖励一次、位置不产生奖励、跨reset计数倒退报错。训练、评测与新检查点加载检查通过。尚未由教师人工观察新版GUI，不作画面验收声明。

## 结论与下一个问题

事件接口和新版奖励连接已完成，奖励来源歧义被消除；这版奖励在40000更新下未解决生存问题。保留失败结果与旧任务，不追加同配置大训练，不自动叠加新奖励或调整网络。下一步检查模型从真实击毁/损命样本构造的目标及动作价值，必要时设计有可达正反馈的小型拦截实验；先定位学习障碍再选择改动。
