# 真实游戏采样批次大小对照

## 问题与假设

复用学习者的collect_batch与collect_transitions，检查真实游戏中改变采样批次大小是否仍能连续收集同样6次动作。批次只是数据分组，不是回合重置；前批next_observation应等于后批observation。

## 环境、配置与唯一变化量

每次1个原生同步第一关GUI；共同初始化IDLE一步，再总共6次RIGHT，每次1tick；0次网络更新。动作ID4，17项观察，K=2及现有尺度不变。每步停留0.4秒、批间1秒、末尾2秒。唯一改变配置是batch-size=2或3；批数随之变化，因此总观看时间略有不同，但不增加游戏步数。

无公共seed/reset，不比较两次进程所有随机状态；同一运行始终复用一个GameClient。原生step需要Action枚举，适配层转换Action(action_id)并请求ticks=1，其余状态及终止标记直接传回旧采样器。保留既有环境与构建，不安装升级。

## 命令与学习者操作

```bash
.venv/bin/python experiments/2026-09-10-chromium-sampling-batches/run.py --batch-size 2
.venv/bin/python experiments/2026-09-10-chromium-sampling-batches/run.py --batch-size 3
```

依次运行两组，预计每组十几秒内结束。比较batch数、每批rows、总rows和actual_ticks；观察批间只是停留观看，之后位置接着变化，没有回到起点。预期第一组3批每批2条，第二组2批每批3条，两次各6条/6tick。若提前真正终止，脚本保留终止步并停止，明确不算完整6步对照。

## 产物、指标与教师结果

产物为终端逐步输出，无文件数据集/检查点。检查相邻观察（含跨批次）衔接、实际动作编号、批间等待快照不变、总条数等于实际tick数，以及奖励总和等于总分增量/100。

2026-09-10教师真实原生GUI模式运行：batch-size2为3批×2条，batch-size3为2批×3条；均6tick、6条，所有原因batch_limit、全部reward=0、最终world_x约1.62，各项断言通过并正常退出。reward=0来自未新增分数，不意味着采样失败。未截图或独立审阅GUI画面；不声称原生终止路径、本轮非空子弹或模型学习已验证。
