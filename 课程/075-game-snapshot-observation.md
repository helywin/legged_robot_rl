# 把游戏快照整理成固定顺序的观察

074学习者回复“继续，我看了可以”，按用户对上一课观察要求的确认记为通过；未收到逐行日志，不补写具体测量值。长期目标仍是DQN控制游戏，本课只接通原始状态到策略输入的转换。

## 为什么已有快照还要整理

快照像游戏的一张详细报表，有飞机位置、控制累积量、分数、敌人和子弹。网络的输入槽位需要有稳定含义：第一项不能这一轮代表x、下一轮又代表分数。我们写一个转换函数，把选定字段按固定顺序变成数字元组，这就是本课的观察编码。

本课只选择飞机自身的四个数字：x、y、水平控制累积量、竖直控制累积量。后两项来自真实接口的keyboard_motion，影响输入释放后的运动，不是真实速度。相同位置的飞机可能带有不同控制累积量，因此下一步运动可能不同。敌人、子弹暂未进入这四项，不能把它称为足以躲弹的观察。

## 用同一组数算清楚

教学样本的position=(2,-4,0)，keyboard_motion=(6,-2)，score=100。实际接口position是世界坐标，不是屏幕像素。本例数字是人为选取，未宣称是真实截取。

先规定输出顺序，再规定表达尺度：位置除以10，控制累积量除以20。两者只是本课指定的固定尺度，不是游戏边界、速度上限或可学习参数，也不保证输出落在[-1,1]。

- x：2/10=0.2；
- y：-4/10=-0.4，保留方向符号；
- 水平控制累积量：6/20=0.3；
- 竖直控制累积量：-2/20=-0.1。

所以输出为(0.2,-0.4,0.3,-0.1)。缩放改变数字的表示，不改变飞机位置。用统一尺度是让输入数字量级更适合一起计算；不同槽位仍是不同含义，数值相等不代表物理量相等。

若只把score从100改为9000，输出不变，因为分数没有被选进本课观察。若位置不变、控制累积量改为(-6,2)，则后两项变成(-0.3,0.1)，前两项不变。被省略的信息不会自动被网络知道。

## 数据怎样流动

真实调用连接为：step返回结果 → result.snapshot → 观察转换函数 → 固定四项数字 → 后续网络输入。本课只练习转换函数。编码读取已有快照，不推进游戏，不修改快照，不计算奖励，也不更新网络参数。输出后续还需转换为模型所用张量，本课不做该连接。

最小算术演示：

```python
position = (2.0, -4.0, 0.0)
motion = (6.0, -2.0)
print(position[0] / 10, position[1] / 10)
print(motion[0] / 20, motion[1] / 20)
```

前两行保存已知教学数据；第三行按x、y顺序表达位置；第四行单独表达两个方向的控制累积量。预期输出为0.2 -0.4和0.3 -0.1，教师标准库运行已核对。这是算术演示，学习者仍需亲手写出可处理不同输入的完整转换。

## 原理追问：子弹数量不固定怎么办

2026-09-09学习者问：“如果是像敌人的子弹这种要怎么生成观察，子弹数量是不固定的”。暂停推进075实作，先澄清数量变化与固定网络输入之间的关系。本节是原理解释，不新增代码训练，不把075标记完成。

原始快照可以包含任意数量的子弹，但当前使用的普通全连接网络要求每次输入长度固定。一种入门方案是预留K个子弹槽位：按明确规则选最多K颗，不足时补空位；每个槽位固定保存相同字段。固定长度是这类网络的输入约定，不是所有神经网络都只能处理固定数量物体。

教学示例取K=2，每槽保存(相对横坐标,相对纵坐标,是否存在)。存在标记也常叫mask，1表示真子弹，0表示补位。这里只解释容量，不把位置三项称为完整躲弹信息。

设飞机在(2,1)，子弹A在(3,3)，B在(-1,1)，C在(2,6)。相对坐标用子弹位置减飞机位置：A=(1,2)，B=(-3,0)，C=(0,5)。距离平方分别为1²+2²=5、(-3)²+0²=9、0²+5²=25，因此按距离从近到远取A、B，得到(1,2,1,-3,0,1)。距离平方足以排序，无需开平方。这里不缩放，只保留数量处理这一层；正式编码可再按约定尺度表达。

若只有A，观察为(1,2,1,0,0,0)；没有子弹，为(0,0,0,0,0,0)。三个场景始终六个数字。为什么不能只补坐标(0,0)？因为它也可能表示真实子弹就在飞机位置；真子弹应为(0,0,1)，空位为(0,0,0)。mask只是输入特征，本身不会自动屏蔽普通全连接网络的计算。

槽位含义应保持为“当前最近”“当前第二近”，而不是某个固定子弹身份。同距可按稳定ID打破平局，以减少无意义换位；距离排名变化仍会换槽。原始ID可用于匹配或排序，不必作为网络输入数值。

代价是超过K的子弹没有进入观察，最近也不一定最危险：更远但快速迎面飞来的子弹可能更值得关注。因此这是可解释的候选方案，不是已确定的完整游戏策略设计。真实接口已有velocity_per_tick（每内部tick的位移量），后续可给每槽加入运动信息；仅凭当前位置不能判断子弹正在靠近还是远离。K及筛选规则需后续实验决定，本节未做原生游戏或策略评测。

其他路线可以将子弹绘成固定大小图像或网格，或使用能汇总可变数量物体的网络；本次不展开。先明确原始集合可变、编码后的槽位固定，以及选取造成的信息损失。


## 原理追问：为什么除以scale

2026-09-09学习者完成编码后追问为什么要除以scale。本次只补充当前概念，不增加新练习或启动网络训练。

除以固定正数相当于改用另一把尺子。例如位置2除以10得到0.2，表示“位置相当于所选参考尺度的0.2倍”。实际位置不变；在未裁剪等处理时，乘回10即可恢复原值（忽略浮点舍入）。同一项中4仍是2的两倍，负值的方向也保留。

为什么网络受益？它的输入参与乘权重、求和，数字的单位和量级会影响同样参数改动造成的输出变化。用另一组专门放大差异的教学输入(200,2)，假设两个权重均为0.1且无偏置：加权和为0.1×200+0.1×2=20.2。其中两个贡献是20和0.2；单独把第一个权重增加0.01，输出增加2；单独把第二个权重增加0.01，输出只增加0.02。

如果第一项除以100、第二项除以1，输入变成(2,2)。同样两个0.1权重的加权和为0.4；同样0.01的单个权重变化都使输出改变0.02。数值缩放能减少仅由输入单位/量级造成的敏感程度差异，通常有助于优化；不表示两个特征应当同等重要，也不保证训练成功。这不是一次真实训练或梯度更新，只是加权和与参数敏感度算术，以上数字已用标准库核对。

注意：保持权重不变时，缩放前后的预测会改变，上例20.2与0.4就是证据。“信息可恢复”不等于“原网络输出保持不变”。若要保持同一个线性函数，当输入x除以s时，可把对应权重w乘以s；实际工程通常从训练开始就固定预处理，训练与使用策略时保持一致。

scale一般根据字段的常见幅度或已知合理范围选取，让典型输入在相近数量级，不要求精确等于1。位置和控制累积量可使用不同尺度；所有字段统一除以同一个数不会消除原来的比例差异。本课10和20仅用于教学，尚未依据真实游戏分布选定。不能用本条样本自身作为除数，也不要每次随意更换尺度；超出参考尺度时输出可以大于1，除法不会自动裁剪。

学习者本次练习实测输出：原始(0.2,-0.4,0.3,-0.1)；控制量反向(0.2,-0.4,-0.3,0.1)；只改分数与原始一致；尺度减半(0.4,-0.8,0.6,-0.2)。这是离线编码练习通过，不是游戏策略训练证据。


## 尺度设计与场景宽高补充

学习者追问如何设计尺度以及场景长宽比能否作为尺度。已解释：先查字段的已知范围，缺乏范围时采集覆盖不同动作的代表数据，再按常见幅度选尺度；不要求精确等于1。场景宽高须与位置采用同一世界坐标单位，不能把窗口像素宽高直接用于世界坐标。仅有16:9等比例不足以确定坐标尺度。

假设中心为(0,0)、世界宽20高30，则自身x/10、y/15可表达相对中心到边界的位置；假如从左下角计数，可按完整宽高表达为[0,1]。这些仅是假设范围，未查证Chromium真实边界。按不同横纵尺度表达后，不应直接使用该坐标计算原世界欧氏距离的排名。子弹运动量与控制累积量仍需按自身含义选尺度。
