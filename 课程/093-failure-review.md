# 从失败回放提出改进假设

本课是轻量复盘，不新增函数。现在要理解：为什么模型得分更高，仍然没有形成可靠的生存行为？先把可见事实与原因猜测分开，下一课094再做一次单因素改进。

## 从总体成绩选一局

092模型平均6607.5分、中位5087.5分，20局中19局死亡。平均值会被高分局抬高，所以选择5075分的seed209，接近中位数。选择规则是代表常见成绩，不是挑最坏画面。

教师用相同模型和任务重跑此种子，得到218决策、21.8模拟秒、5075分、hero_dead，与学习者评测逐局记录一致。诊断只记录行为，不训练；这不是学习者新增实作。

## 实际发生了什么

1. 前两步都是动作11（向下并开火），第3步动作2（向下），到达y=-7.5的底边。
2. 全局152/218步选择向下开火；含开火动作合计156步，说明并非完全不开火，也并非始终只有一个动作。
3. 204/218步结束位置满足`abs(x)>=9.5或abs(y)>=7`，约93.6%位于边缘附近。该比例按决策计，不是碰撞率，也不能证明边缘必然危险。
4. 可见生命计数在85、92、134、159、218步各下降1，这五步即时奖励均为0；最终hero_dead。

## 用同一局解释奖励告诉了它什么

当前奖励是得分增量除以100。第118步得分从0变2500，所以奖励为`(2500-0)/100=25`；第134步损命但分数仍是2500，所以奖励为`(2500-2500)/100=0`。网络训练时只从传入的奖励和后续价值构造目标，不会因为人觉得损命很糟就自动得到一个负奖励。

这不等于模型完全没有生存动机：死亡会终止后续得分，终止经验不再加后续价值；非终止损命的后果也可能通过未来经验传播。只是当前奖励没有直接区分“这一刻掉了一条命”和“这一刻没有得分”。因此，得分提高并不能单独证明学会躲避。

已知事实是该局长期贴边且最终死亡。候选解释包括训练只有500次更新、尚未学会有效动作，以及纯得分反馈对损命后果表达不直接。单局不能分辨这些原因，更不能证明是贴边导致死亡。

## 现在做什么

用已有GUI回放看一次同一局，无需修改代码：

```bash
.venv/bin/python exercises/chromium_dqn/play.py --run --seed 209
```

主要看开局冲到底边、随后贴边移动与损命的过程；模型会换动作，不要求每次损命都能凭肉眼定位碰撞原因。教师本次验证了原生逐步数据，尚未亲自核对这局GUI画面。

本课理解重点：先描述行为，再提出原因假设，最后用对照实验验证；看到失败就同时改奖励、网络和训练量，会不知道是哪一项起效。

下一课094只选择一个变化量。优先检验训练量是否不足：保持观察、奖励、网络和种子不变，提高训练预算后按相同规则比较；本课尚未开始该训练，也未修改奖励。
