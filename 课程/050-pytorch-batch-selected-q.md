# 一批经验怎样逐行取得实际动作 Q 值

## 本课只解决一个问题

第 49 课已经用一条经验更新了一次在线网络。真实 DQN 从经验回放中随机抽取的通常不是一条经验，而是多条经验组成的**批量**（batch）。

本课只回答：

> 两条经验一起进入网络后，怎样为每一条经验分别取出它当时实际执行动作的 Q 值？

这一步不计算 target、不调用 `backward()`，也不更新参数。先把“批量中的行和动作列怎样对应”彻底看清。

## 1. 单条经验为什么很简单

一条观察进入两动作网络：

```text
observation.shape = (2,)
q_values.shape    = (2,)

q_values = [0.10, -0.05]
executed_action = 1
selected_q = q_values[1] = -0.05
```

这里只有一行隐含的数据，所以一个动作编号就足够指出要取哪个值。

## 2. 两条经验一起进入网络后发生了什么

固定两条观察：

```text
第 0 条 observation = [ 0.2, -0.1]
第 1 条 observation = [-0.3,  0.4]
```

把它们上下堆起来：

```text
observations = [
    [ 0.2, -0.1],
    [-0.3,  0.4],
]

observations.shape = (2, 2)
```

第一个 `2` 表示有两条经验，第二个 `2` 表示每条观察有两个数字。网络会对每一行分别计算两个动作 Q 值：

| 经验行号 | 动作 0 的 Q 值 | 动作 1 的 Q 值 |
| ---: | ---: | ---: |
| 0 | 0.10 | -0.05 |
| 1 | 0.60 | 0.70 |

因此：

```text
q_values.shape = (2, 2)
```

虽然输入和输出恰好都是 `(2, 2)`，两个维度的职责不同：

```text
observations: (经验数量, 每条观察的数字数量)
q_values:     (经验数量, 动作数量)
```

不能只看数字相同就认为两个维度含义相同。

## 3. 每条经验可以执行不同动作

假设回放缓冲区保存的实际动作是：

```text
executed_actions = [1, 0]
```

普通语言含义是：

- 第 0 条经验执行动作 1，应取第 0 行第 1 列，即 `-0.05`；
- 第 1 条经验执行动作 0，应取第 1 行第 0 列，即 `0.60`。

最终需要：

```text
selected_q_values = [-0.05, 0.60]
selected_q_values.shape = (2,)
```

这里不是从整张矩阵中找最大值，而是按照每条历史经验中记录的动作，分别取得对应列。

## 4. 为什么不能直接写 `q_values[executed_actions]`

对二维张量只写一组方括号时，PyTorch 把索引用在第 0 维，也就是“经验行”：

```text
q_values[executed_actions]
= q_values[[1, 0]]
= 先取第 1 行，再取第 0 行
```

得到的是交换顺序后的两整行：

```text
[
    [0.60,  0.70],
    [0.10, -0.05],
]
```

这不是想要的 `[-0.05, 0.60]`。错误的根源不是数值，而是索引缺少“每一行分别选择哪一列”的信息。

## 5. `gather` 做的事情是什么

可以把 `gather` 直观理解成：**拿着一张逐行取货单，从指定维度收集元素。**

当前取货单是：

| 要处理的行 | 这一行要取的动作列 |
| ---: | ---: |
| 0 | 1 |
| 1 | 0 |

动作张量原来形状为 `(2,)`：

```text
[1, 0]
```

为了让它明确表示“两行各指定一列”，先临时变成 `(2, 1)`：

```text
[
    [1],
    [0],
]
```

然后沿动作所在的第 1 维收集，每行得到一个值，结果暂时是 `(2, 1)`：

```text
[
    [-0.05],
    [ 0.60],
]
```

最后去掉只用于索引的单元素维度，得到 `(2,)`：

```text
[-0.05, 0.60]
```

## 6. 数据流和不变量

```text
两条观察 (2, 2)
    ↓ 在线网络逐行前向计算
每条经验的全部动作 Q 值 (2, 2)
    ↓ 每行使用自己的实际动作编号
每条经验的 selected Q 值 (2,)
```

这一过程中：

- 网络参数只被读取，不会改变；
- 动作编号只负责索引，不参与梯度计算；
- 选出的 Q 值仍是张量，并保持到网络参数的计算图；
- 第 0 条和第 1 条经验不会互相覆盖，它们只是一起计算。

## 7. 代码职责对应

| 操作 | 读取什么 | 产生什么 |
| --- | --- | --- |
| 网络批量前向 | `(批量, 观察数)` | `(批量, 动作数)` |
| 给动作编号增加一维 | `(批量,)` | `(批量, 1)` |
| 沿动作维逐行收集 | Q 值矩阵和动作列号 | `(批量, 1)` |
| 去掉单元素维度 | `(批量, 1)` | `(批量,)` |

## 一句话总结

批量 Q 值矩阵的第 0 维是经验行、第 1 维是动作列；训练时必须为每一行使用它自己的历史动作列，而不能把动作编号误当成经验行号。
