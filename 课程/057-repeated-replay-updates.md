# 多次回放更新怎样与目标同步组成循环

## 本课只学“一次更新之后接什么”

第 55 课已经有了一次真实回放更新：

```text
抽样 → 张量 → loss → backward → optimizer.step
```

第 56 课已经有了定期同步：

```text
更新编号能被间隔整除
→ 复制在线参数到目标网络
```

本课不增加新的 DQN 公式，只把两者放进同一个循环：

```text
第 1 次在线更新 → 检查同步
第 2 次在线更新 → 检查同步
第 3 次在线更新 → 检查同步并复制
第 4 次在线更新 → 检查同步
……
```

这还不是完整环境训练。回放缓冲区里的三条经验是预先放好的，循环只重复抽样和学习，环境还没有持续产生新经验。

## 1. 先区分三种“次数”

以后看完整 DQN 代码时，常会同时看到三种计数：

| 计数 | 什么时候增加 | 本课是否使用 |
| --- | --- | --- |
| 环境 step 数 | 向环境执行一次动作后 | 否 |
| episode 数 | 一轮从 reset 走到结束后 | 否 |
| 在线参数更新数 | optimizer 真正修改一次在线参数后 | 是 |

本课的 `update_number` 只计算在线参数被更新了几次。不能因为变量也是数字，就把环境 step 数或 episode 数随意代入同步条件。

原因是：目标网络要限制的是“在线参数变了多少次”。如果环境走了 100 步，但回放缓冲区还不够大、optimizer 一次也没运行，那么目标网络没有新在线参数需要复制。

## 2. 一轮循环的完整因果顺序

本课每一轮必须保持这个顺序：

```text
1. 从回放缓冲区抽样
2. 按字段变成五个张量
3. 用当前在线网络计算预测
4. 用当前目标网络计算 target
5. loss.backward() 写入在线参数.grad
6. optimizer.step() 更新在线参数
7. 记录本次 loss
8. 根据在线更新编号判断是否同步目标网络
9. 进入下一轮
```

第 3 次同步时，第 3 次 loss 使用的仍是同步前的目标参数。因为正确的时间顺序是：

```text
用旧目标参数完成第 3 次 target 和在线更新
→ 更新计数变成 3
→ 将新在线参数同步给目标网络
→ 第 4 次 target 才使用这份新目标参数
```

如果先同步再做第 3 次更新，目标参数实际上只包含前 2 次学习结果，“每 3 次更新同步”的时间含义就被改了。

## 3. 循环为什么从 1 数到 `update_count`

Python 的 `range(start, stop)` 包含开始数，但不包含结束数。

```python
list(range(1, 7))
```

结果是：

```text
[1, 2, 3, 4, 5, 6]
```

因此本课的循环头是：

```python
for update_number in range(1, update_count + 1):
```

从 1 开始是因为“第 1 次更新”比“第 0 次更新”更符合我们现在的时间定义；也能让第 3、6 次直接对应同步点。

## 4. 为什么同一个随机数对象要跨轮使用

创建一次：

```python
random_generator = random.Random(7)
```

这个对象不只保存种子 `7`，还保存“随机序列已经走到哪里”。

```text
第 1 次 sample 读取随机序列的前一段
→ random_generator 记住新位置
→ 第 2 次 sample 从新位置继续
```

如果在循环里每次重新写：

```python
random_generator = random.Random(7)
```

就相当于每轮都把随机序列倒回起点。在同一个缓冲区上，往往会反复抽到同一组元素，这会破坏我们想要混合不同旧经验的目的。

> [!note] 可重现不等于每轮完全一样
> 固定种子的意思是整个随机序列可重现，不是让序列中的每一次抽样都相同。

## 5. `loss.item()` 读出的是哪一个 loss

`train_from_replay()` 的内部顺序是：

```text
用当前在线参数前向计算
→ 得到 loss
→ loss.backward()
→ optimizer.step() 改变参数
→ 返回刚才那个 loss
```

因此：

```python
loss_value = result[4].item()
```

读出的是“这次参数更新使用的 loss”，不是使用新参数重新计算的 loss。

`.item()` 只把单元素张量中的数字取成 Python `float`，便于放进列表、打印或写日志。它不会再调用 `backward()`，也不会再让 optimizer 更新一次。

## 6. 用固定数据跟 6 次真实回放更新

本课继续使用第 55 课的三条经验、每次抽 2 条、折扣因子 `0.9`、学习率 `0.1`、随机种子 `7`，并每 3 次在线更新同步目标网络。

实际参考轨迹是：

| 在线更新编号 | 本次更新使用的 loss | 更新后同步 | 同步检查后两网参数相同 |
| ---: | ---: | --- | --- |
| 1 | 0.641800 | 否 | 否 |
| 2 | 0.511266 | 否 | 否 |
| 3 | 0.379486 | 是 | 是 |
| 4 | 0.378828 | 否 | 否 |
| 5 | 0.261590 | 否 | 否 |
| 6 | 0.209546 | 是 | 是 |

第 3 次同步后两网相同，但第 4 次 optimizer 只改变在线网络，于是它们又分开。第 6 次同步后再次相同。

### loss 下降不是这个循环的永久保证

在这组固定小数据中，6 个 loss 确实一直下降。但真实 DQN 每轮会抽到不同难度的经验，目标网络同步后 target 也可能变化。

所以以后看到：

```text
某一次 loss 比上一次高
```

不能立即推断程序写错。单批 loss 表示当前抽到的这批预测与当前 target 的差距，不是整个策略能力的直接成绩。

## 7. 随机抽样为什么允许重复使用经验

“回放”的意思本来就是：一条环境经验不是训练一次就删除，而是留在缓冲区中，以后还可能再次被抽到。

先区分两种“重复”：

- **同一批内：** `random.sample(...)` 不会在一次调用中重复抽同一条；
- **不同更新之间：** 上一次抽到的经验不会从缓冲区删除，下一次可以再抽到。

第二种重复是有意保留的，因为获得一条环境经验可能比做一次张量计算更贵。允许旧经验被多次使用，能让一次交互产生的信息不至于用一次就丢掉。

随机化解决的不是“永不重复”，而是“下一批不要永远固定地只取最新的连续几步”。环境连续几步往往很相似；从更大的新旧经验池中随机混合，能让一批更新同时看到不同时间和不同状态的经验。

### 本课 3 条经验实际重复了多少次

固定种子 `7`、3 条经验、每批 2 条、共 6 次更新的实际抽样是：

| 更新次数 | 抽到的缓冲区位置 |
| ---: | --- |
| 1 | `[1,0]` |
| 2 | `[1,0]` |
| 3 | `[0,2]` |
| 4 | `[1,0]` |
| 5 | `[2,0]` |
| 6 | `[0,2]` |

先用普通语言说要算什么：每次更新用 2 条，连续更新 6 次，所以网络总共看到 12 个“经验使用位置”。

```text
总使用次数 = 更新次数 × 每批经验数
             = 6 × 2
             = 12
```

这 12 次实际分配为：

```text
经验 0：6 次
经验 1：3 次
经验 2：3 次
```

随机抽样不保证在这么少的更新中每条刚好各用 4 次。它只让每条都有被选中的机会；短期计数可以不均匀。

### 怎样估算平均重用程度

需要三个来自训练设置的数：

- $N$：缓冲区当前有多少条经验；
- $B$：每次更新抽多少条；
- $U$：共进行多少次更新。

先计算总使用位置 $U \times B$，再均分到 $N$ 条经验，每条的平均被使用次数是：

$$
\frac{U \times B}{N}
$$

代入本课数字：

$$
\frac{6 \times 2}{3}=4
$$

这个 `4` 是随机抽样的平均期望，不是每条在一次小实验中必须恰好出现 4 次。

### 什么时候重复会变成问题

`update_count` 比样本数大，本身不是错误。更需要看的是：环境是否持续增加新经验，以及每条经验平均被重用多少次。

如果像本课脚手架一样：

```text
缓冲区永远只有 3 条固定经验
→ 却执行几千或几万次更新
```

网络就可能只会越来越贴合这 3 条旧数据，却没有获得新状态、新奖励和失败情况的信息。随机改变抽样顺序不能创造新信息，目标网络也不能。

真实在线 DQN 会用几个边界限制这个问题：

1. 环境继续 `step()`，把新经验不断加入缓冲区；
2. 缓冲区容量有限，满后逐渐淘汰最旧经验；
3. 不在只有极少数经验时立即开始高强度更新；
4. 控制“新产生多少经验”与“做多少次参数更新”的比例；
5. 最后用不更新参数的独立评估检查策略，不用训练 loss 代替能力评估。

本课的固定 3 条经验只是为了让调用顺序、同步点和 loss 可重现，不是真实 DQN 应该采用的数据规模。

## 8. 代码与机制一一对应

| 代码动作 | 读取什么 | 产生什么 | 会改变什么 |
| --- | --- | --- | --- |
| `train_from_replay(...)` | 缓冲区、两网、optimizer、随机状态 | 本次中间张量和 loss | 在线参数、optimizer 状态、随机状态 |
| `result[4].item()` | 本次 loss 张量 | Python 浮点数 | 不改参数 |
| `maybe_sync_target_network(...)` | 更新编号和两网参数 | 本次是否同步 | 仅在到期时复制目标参数 |
| `parameters_match(...)` | 两网所有参数 | 布尔值 | 什么都不改 |

这个循环中，回放缓冲区不删除经验；在线网络每轮更新；目标网络只在第 3、6 轮被复制；随机数对象每轮向后推进内部状态。

## 一句话总结

多次回放更新循环每轮先让当前目标参数参与 target 计算并更新在线参数，再根据真实在线更新次数决定是否同步；循环中始终复用同一个随机数对象，让固定种子产生可重现但不是每轮相同的抽样序列。
