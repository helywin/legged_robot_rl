# reset：重置环境，但不重置学习

长期方向仍是让策略通过交互学会游戏控制，再迁移这些学习方法到四足任务。本课只澄清已经使用过的 `reset()`：什么属于新一局的起点，什么应该跨局保留。不实现新接口，不创建固定答案检查器。

## 1. 回到出生位置，为什么还不够

好比重新摆好棋盘不等于让棋手失忆：场景要重新开始，学习成果要保留。

采用假想固定摄像机飞机游戏，不代表 Chromium B.S.U. 的已核实机制。上一局结束时：飞机横坐标90、生命0、画面中残留8发敌弹、左键仍处于按下状态。新一局规定：横坐标50、生命3、无旧敌弹、无残留按键。

如果只把飞机移回50，旧敌弹可能马上命中它；如果左键没释放，即使新策略没有选择左移，飞机也可能继续向左。此时画面看着重开了，实际状态却不是约定的新起点。

`reset()` 的职责不是“把某几个数赋为零”，而是恢复任务约定的初始状态，并返回属于这个新状态的观察。生命初值就是3，不是0；允许随机初始位置的任务也不必每次回到同一个坐标。

## 2. 观察历史也不能跨局拼接

沿用上一局末尾横坐标90、新局横坐标50的数字。假设通常两张相邻观察相隔0.1秒。

如果误把这两张图当成同一局相邻时刻，会推算出：

$$
速度估计=\frac{50-90}{0.1}=\frac{-40}{0.1}=-400\;\text{像素/秒}
$$

这个巨大左移速度不是动作造成的，而是重新出生造成的位置跳变。策略如果依赖前后帧判断运动，就会拿到一条假的运动线索。

若策略要求两帧输入，一种初始化约定是用新局首帧填满历史，即 `[首帧, 首帧]`。这个约定让帧差为0，但不证明真实速度为0；有随机初速度的任务仍需要额外运动信息，或等待约定的有效后续观察。关键是不能借用上一局的末帧。

最小 Python 算术对照（只是教师演示，不是学习者训练）：

```python
old_episode_x = 90
new_episode_x = 50
frame_interval = 0.1
false_velocity = (new_episode_x - old_episode_x) / frame_interval
print(false_velocity)  # 预期 -400.0
```

前两行分别来自两局，不是连续运动；第三行本来只适用于同局相邻采样；第四行揭示错误拼接怎样制造假速度；最后一行只检查算术，不验证游戏接口。

## 3. 新一局清什么，留什么

| 数据 | 新一局处理 | 原因 |
|---|---|---|
| 位置、生命、敌弹、关卡状态 | 按初始规则恢复 | 定义新任务起点 |
| 残留按键、未消费的旧事件 | 清理或按接口规则同步 | 不让上局输入和反馈污染本局 |
| 当前局观察历史、局内计时与回报累计 | 重新初始化 | 不跨局拼出假运动或混算成绩 |
| 在线网络、目标网络参数 | 保留 | 它们是已经学到的知识 |
| optimizer内部状态 | 通常保留 | 继续同一次训练，而不是重新训练 |
| DQN回放缓冲区 | 通常保留 | 旧局真实经验仍能用于学习 |
| 总环境步数、探索衰减进度 | 按训练计划继续 | 重开游戏不等于训练时间归零 |

这些数据由不同组件负责：游戏重开不自动保证 Python 的历史缓存清空；`env.reset()` 也不应该顺手重新创建网络。这里说的是同一训练任务中的正常回合切换，不是换任务或从头启动训练。

## 4. 旧经验要留，但不能把两局缝成一步

正确记录：先保存旧局最后一步真实的 `(观察, 动作, 奖励, 结束观察, 结束标记)`，再重置，使用新局首观察作下一局起点。

新局飞机从90变成50不是旧动作产生的后果，不能把新局首观察冒充旧局最后一步的动作后观察。自然终止时 DQN 的未来项虽然被屏蔽，仍应保存正确边界；在需要保留未来估计的时间截断场景，混用重置观察还会直接污染目标。

因此，“清空本局帧历史”和“保留跨局回放经验”并不矛盾：前者防止虚构连续性，后者保留已经发生过的真实动作后果。

## 5. 可比较不等于每次完全一样

初始位置可以按同一规则随机产生。可比较意味着起点遵守约定、随机变化受控、没有上局残留，而不是强制所有回合相同。固定种子有助于复现，但外部游戏还可能受输入时序影响；仅设置种子不能证明完全可复现。

以后真实接入时，需要核实重开完成后的生命、关卡、对象、输入释放、首帧时序和局内缓存，而不是仅凭“按了重开键”或“等待了两秒”判断成功。本课未启动游戏，也未验证这些接口。

一句话：**reset重新摆好场景，不抹掉策略的学习；新旧回合的观察不能伪装成连续运动。**
