# 环境为什么要先填充回放缓冲区再训练

## 本课回答第 57 课留下的数据重用问题

第 57 课中，回放缓冲区固定只有 3 条经验，6 次更新共使用了 12 个经验位置。这证明了调用循环，但如果一直这样训练，并不会获得新信息。

真实在线 DQN 要并行推进两件事：

```text
数据侧：环境继续产生新经验并放进缓冲区
学习侧：从新旧经验中抽样并更新网络
```

但训练刚开始时，缓冲区是空的。因此本课只学一个新概念：**回放预填充**，即先积累到设定经验数，再允许第一次参数更新。

## 1. 为什么不能从第 1 条经验立即训练

假设 batch size 是 2。缓冲区只有 1 条经验时：

```text
需要抽 2 条
实际只有 1 条
→ 根本无法组成一批
```

如果刚好收集到 2 条就开始，虽然能抽，但每批只有唯一种成员组合：

```text
缓冲区 = [经验0, 经验1]
每批抽 2 条
→ 每次都必须用经验0和经验1
```

随机数只能改变两条在列表里的先后顺序，无法改变批次成员。网络会从最早、最局部的两条经验开始反复拉动参数。

## 2. 预填充阶段到底在做什么

本课设定：

```text
warmup_size = 4
batch_size = 2
```

这表示：

```text
缓冲区少于 4 条
→ 环境继续交互并保存经验
→ 不执行 backward 和 optimizer.step

缓冲区达到 4 条
→ 本次新经验已经存好
→ 允许从 4 条中随机抽 2 条
→ 开始第 1 次在线参数更新
```

“预填充”不是神经网预训练，也不是程序睡眠等待。环境仍在产生 observation、action、reward 和 next observation，只是这些经验暂时先存起来，没有立即反向更新网络。

## 3. 同一组数字的 6 步时间线

经验流按环境时间顺序一条一条到来。固定 `warmup_size=4`、`batch_size=2`、目标同步间隔为 3 次在线更新：

| 环境 step | 新经验存入后的数量 | 本次训练 | 在线更新编号 | 本次同步 |
| ---: | ---: | --- | ---: | --- |
| 1 | 1 | 否 | 0 | 否 |
| 2 | 2 | 否 | 0 | 否 |
| 3 | 3 | 否 | 0 | 否 |
| 4 | 4 | 是 | 1 | 否 |
| 5 | 5 | 是 | 2 | 否 |
| 6 | 6 | 是 | 3 | 是 |

这张表说明：

- 环境 step 每轮都增加，因为每轮都来了新经验；
- 在线更新数前 3 轮一直是 0，因为 optimizer 还没有运行；
- 环境 step 4 才对应在线更新 1；
- 环境 step 6 对应在线更新 3，所以这时才是第一个目标同步点。

这再次说明：目标同步应该看真正的参数更新数，不能直接拿环境 step 数代替。

## 4. 为什么必须先存新经验再判断训练

在环境 step 4 开始时，缓冲区里只有前 3 条。第 4 条经验已经由环境产生，正确顺序是：

```text
完成环境交互得到第 4 条经验
→ replay_buffer.add(第 4 条)
→ len(replay_buffer) 变成 4
→ 达到 warmup_size
→ 允许训练
```

如果先检查数量再存数据，环境 step 4 看到的仍是 3，第一次训练就会被错误推迟到 step 5。

## 5. Python 代码怎样表达这条时间线

缓冲区已实现 `__len__()`，所以直接读数量：

```python
buffer_size = len(replay_buffer)
```

判断数量是否达标：

```python
if len(replay_buffer) >= warmup_size:
    ...
```

只在真正进入训练支路时增加更新编号：

```python
update_number += 1
```

它等价于：

```python
update_number = update_number + 1
```

这三个 Python 操作不会自动训练网络。它们只负责决定是否调用已经完成的 `train_from_replay(...)`。只有这个函数内部的 `backward()` 和 `optimizer.step()` 会改变在线参数。

## 6. 新数据和旧数据怎样同时出现

达到预填充数量后，环境不会停止产生数据。本课在 step 4、5、6 的顺序是：

```text
先加入当前最新经验
→ 再从整个缓冲区随机抽样
```

随机批次可能包含刚刚加入的经验，也可能包含以前的经验。这正是回放的目的：不抛弃旧信息，同时让抽样池随环境交互不断获得新信息。

本课的三次 loss 是：

```text
0.569000 → 0.981785 → 0.481624
```

第 2 次 loss 比第 1 次高，不代表预填充失败。第 2 次时缓冲区已加入新经验，随机抽到的批次也不同；单批 loss 可以因为数据难度不同而上下波动。

## 7. `warmup_size` 为什么不只是 `batch_size`

`warmup_size >= batch_size` 是“代码能抽出一批”的最低条件，不是“数据已经足够多样”的证明。

以每批 2 条为例：

- 缓冲区只有 2 条时，批次成员只能是这 2 条；
- 缓冲区有 4 条时，可以从更多不同的经验对中抽样；
- 真实任务中，可能需要比 4 大得多的预填充数量。

具体多少不能只凭课程中的数字猜。以后进入 CartPole 时，我们会把预填充数量、batch size、缓冲区容量、交互步数和更新次数一起记录，不会把它们混成一个参数。

## 一句话总结

回放预填充让环境先提供足够数量的起始经验，预填充期间只收集而不更新参数；达到门槛后，每轮仍先加入新经验，再从不断变化的新旧经验池中随机抽样并更新。
