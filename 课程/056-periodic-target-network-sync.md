# 目标网络为什么只按间隔同步

## 本课只回答“什么时候复制参数”

第 55 课已经把一次回放更新连通：

```text
回放抽样
→ 五个批量张量
→ 在线网络预测
→ 目标网络提供未来估值
→ loss
→ backward
→ optimizer.step 改变在线参数
```

但每次 `optimizer.step()` 之后，两个网络的参数就不一样了：

```text
在线网络：刚学到了新参数
目标网络：仍保留较旧参数
```

本课要解决的唯一问题是：

> 为什么不每次立即复制，也不让目标网络永远不变，而是每隔固定次数复制一次？

这里的“同步”只指把在线网络的当前参数值复制到目标网络。同步不使用新经验、不计算 loss，也不调用 `backward()`。

## 1. 为什么不每次更新后立即同步

目标网络的作用是让“用来计算未来价值的参考”暂时固定。

如果每次在线网络更新后都立即复制：

```text
在线参数改变
→ 立即复制到目标网络
→ 下一次 target 也跟着改变
```

那么目标网络几乎又变成了在线网络的实时副本。我们仍然写了两个 Python 对象，但“暂时固定参考”这个效果基本消失了。

这就像用一把尺测量距离，每测一次就马上改变尺子的刻度。你仍然能计算出数字，但参考标准一直跟着被测对象移动。

## 2. 为什么也不能永远不同步

在线网络已经从很多经验中学到新参数后，如果目标网络永远保留最初的随机参数：

```text
在线网络逐步学习
→ 目标网络永远留在起点
→ 未来 Q 值长期使用过时参考
```

固定参考变得稳定了，但它不再反映在线网络已经学到的新估值。这叫“太旧”，不叫“稳定”。

## 3. 定期同步是两个需求的折中

定期同步的时间结构是：

```text
同步一次
→ 目标参数固定若干次在线更新
→ 再同步一次
→ 再次固定若干次
```

这同时满足：

- 两次同步之间，target 的未来估值使用固定参数；
- 到达同步点时，目标网络又能获得在线网络已经学到的新参数。

“间隔多少最好”不是本课要猜的固定答案。真实间隔是训练配置，以后要通过小规模训练稳定性和评估结果判断。本课只学会准确执行一个已给定的间隔。

## 4. 用一个权重手动跟 6 次更新

为了只观察同步，本课把其他因素全部固定：

- 在线权重初始值：`1.0`；
- 目标权重初始值：`1.0`；
- 每次受控地让在线权重增加：`0.5`；
- 同步间隔：每 3 次在线参数变化后同步。

先不运行 Python，亲手展开：

| 更新次数 | 在线权重变化后 | 是否到同步点 | 同步后目标权重 |
| ---: | ---: | --- | ---: |
| 0 | 1.0 | 初始化 | 1.0 |
| 1 | 1.5 | 否 | 1.0 |
| 2 | 2.0 | 否 | 1.0 |
| 3 | 2.5 | 是 | 2.5 |
| 4 | 3.0 | 否 | 2.5 |
| 5 | 3.5 | 否 | 2.5 |
| 6 | 4.0 | 是 | 4.0 |

关键不是记住这些数，而是看出三段时间：

```text
更新 1、2：在线变，目标不变
更新 3：在线先变成 2.5，然后目标一次复制成 2.5
更新 4、5：在线继续变，目标仍停在 2.5
更新 6：目标再一次复制成 4.0
```

> [!note] 同步时机
> 本课约定先完成第 3 次在线更新，再同步。因此第 3 次更新本身使用的仍是同步前的目标参数；第 4 次更新才开始使用新目标参数。

## 5. Python 怎样判断“每隔 3 次”

Python 的 `%` 返回除法的余数：

```python
1 % 3  # 1，还差两次
2 % 3  # 2，还差一次
3 % 3  # 0，刚好整除
4 % 3  # 1，进入下一周期
```

所以同步条件是：

```python
update_number % sync_interval == 0
```

代入 `update_number=3`、`sync_interval=3`：

```text
3 % 3 = 0
0 == 0 得到 True
→ 本次同步
```

代入 `update_number=4`：

```text
4 % 3 = 1
1 == 0 得到 False
→ 本次不同步
```

`%` 不是 PyTorch 接口，是 Python 算术运算符，Python 3.6 已经支持。

## 6. PyTorch 怎样复制整个网络的参数

网络可能有很多层，所以不应该手写“第一个权重复制到哪里”。PyTorch 提供两个配对接口：

```python
online_state = online_network.state_dict()
target_network.load_state_dict(online_state)
```

### `state_dict()` 产生什么

`state_dict()` 按名字列出网络要保存或复制的状态。本课只有一个无偏置线性层，因此可见内容类似：

```text
online_state = {
    "linear.weight": tensor([[2.5000]])
}
```

`"linear.weight"` 是参数在网络结构中的名字，`2.5` 是当前在线参数值。

### `load_state_dict(...)` 做了什么

```python
target_network.load_state_dict(online_state)
```

它在目标网络中找到同名的 `"linear.weight"`，再把数值 `2.5` 复制进去。

发生的是：

```text
在线参数对象：保留
目标参数对象：也保留
目标参数里的数字：被复制为在线参数的当前数字
```

两个网络不会因此变成同一个对象。这一点很重要：第 3 次同步到 `2.5` 以后，第 4 次在线参数继续变成 `3.0`，目标参数仍能独立停在 `2.5`。

> [!warning] 不是 Python 变量赋值
> `target_network = online_network` 只会让两个变量指向同一个网络对象。以后在线参数一变，所谓“目标网络”也会同时变，暂时固定的作用就消失了。

## 7. 同步与 loss、梯度、optimizer 的边界

普通在线训练步是：

```text
在线参数
→ 前向计算
→ loss 保留到在线参数的计算图
→ backward 写入在线参数.grad
→ optimizer.step 读取 grad 并更新在线参数
```

目标网络同步是另一件事：

```text
到达同步间隔
→ 读取在线网络当前参数值
→ 直接复制到目标网络
```

同步时：

- 不产生新 loss；
- 不调用 `backward()`；
- 不使用 optimizer；
- 不会改变回放缓冲区；
- 不代表目标网络自己“学了一次”。

目标网络没有从这批经验反向学习。它只在到期时接收在线网络已经学到的参数副本。

## 一句话总结

目标网络定期同步，是为了同时获得“若干次更新内参考固定”和“隔一段时间接收新估值”；同步只复制参数数值，不计算梯度，也不会让两个网络变成同一个对象。
