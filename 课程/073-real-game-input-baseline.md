# 真实游戏方向输入与释放

本课开始实际游戏行为实验。目标不是得高分，而是弄清右移输入怎样生效，以及松开后发生什么。

“按下”通常表示开始保持一种输入状态，“松开”表示结束它。未来一次动作不能只发送按下而忘记释放，否则下一次选择保持时旧输入可能仍生效。但具体运动是否立即停止必须在游戏中观察，不能从按键名字推断。

假想无惯性的运动规则：每个游戏更新向右2像素，起点50，保持3次更新，位置依次52、54、56；释放后若不再移动，则保持56。这只是帮助理解按住与释放，不是Chromium实际速度或帧数。按0.2秒也不保证运行3次更新。

本机为Wayland桌面，存在xdotool，但尚未验证游戏窗口后端及自动输入。所以先做人工输入基线；否则游戏本身不接受方向键和输入工具没送到窗口会表现为同一个“没动”。本课不增加库、不注入桌面按键，不改游戏源码。

学习者实验入口：[[experiments/2026-09-07-chromium-input-baseline/README]]。里面包含完整命令、唯一变化量、操作步骤、异常判断和结果表。请真实操作并描述右键、松开、左键的现象；不需要填写代码或猜接口。

2026-09-07学习者GUI结果：不输入不动，按得久动得久，松开停止，上下左右与斜移均可。人工输入基线通过，本课completed；没有自动输入、截图测量或模型训练证据。

这说明程序动作必须描述完整的方向键状态。例如从右上切换为右移，要释放上键、保持右键；切换为不移动，要释放所有方向键。“不移动”不能只理解为不发送新事件，否则旧按键可能仍保持。八个方向加不移动可作为候选的9种移动动作，尚未决定开火组合或斜移速度规则。
