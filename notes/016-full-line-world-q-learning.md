# 完整的走格子 Q-learning 训练循环

## 本课目标

前面已经分别看懂环境交互、ε-greedy 和一次 Q 值更新。本课不增加新的算法公式，只把这些部件放入循环，让 Q 表通过多轮练习从全零开始变化。

## 最重要的两个循环

完整训练有两层循环：

```text
训练很多个 episode
└─ 每个 episode 里面执行很多个 step，直到结束
```

- 外层循环负责重新开始一轮练习；
- 内层循环负责在这一轮中不断观察、选动作、接收奖励和更新 Q 值。

> [!important] Q 表不能每轮清零
> Q 表只在整个训练开始前创建一次。每个 episode 调用 `reset()` 时，只重置小人的位置和步数；如果同时清空 Q 表，上一轮学到的经验就会消失。

## 一个 step 中的顺序

```text
1. 读取当前观察对应的 Q 表一行
2. 用 ε-greedy 选择动作
3. 环境执行动作，返回新观察、奖励和是否结束
4. 读取下一观察对应的一行，找最高 Q 值
5. 计算目标值
6. 更新当前观察和动作对应的一个 Q 值
7. 把新观察作为下一次循环的当前观察
```

如果第 3 步已经到达终点，第 4 步的未来价值按零处理。

## 对应的简化代码

```python
q_table = 创建全零Q表()

for episode in range(训练轮数):
    observation = env.reset()
    done = False

    while not done:
        action = 使用epsilon_greedy选择动作()
        new_observation, reward, done = env.step(action)
        target = 计算目标值()
        q_table[observation][action] = 更新一个Q值()
        observation = new_observation
```

真正可运行的标准库版本位于 `examples/train_line_world_q_learning.py`。

## 训练和评估必须分开

训练时：

- `epsilon=0.20`，保留随机探索；
- 每个 step 都更新 Q 表。

评估时：

- 关闭探索，只选当前 Q 值最高的动作；
- 不再更新 Q 表；
- 记录是否到达目标、用了多少步和总奖励。

这样评估看到的是训练后策略本身的行为，而不是训练时的随机尝试。

## 运行方式

```bash
python examples/train_line_world_q_learning.py
```

默认设置为：

| 参数 | 数值 | 作用 |
| --- | ---: | --- |
| 训练轮数 | `500` | 重复练习 500 个 episode |
| ε | `0.20` | 每次决策有 20% 概率探索 |
| 学习率 | `0.20` | 每次吸收目标差距的 20% |
| 折扣因子 | `0.90` | 保留下一位置价值的 90% |
| 随机种子 | `0` | 让本次训练可以复现 |

## 本次实际运行结果

训练 500 个 episode 时：

```text
训练期间到达目标: 497/500
```

得到的 Q 表是：

| 位置 | `left` | `right` | 当前最佳动作 |
| ---: | ---: | ---: | --- |
| 0 | 0.622 | 0.702 | `right` |
| 1 | 0.622 | 0.791 | `right` |
| 2 | 0.702 | 0.890 | `right` |
| 3 | 0.791 | 1.000 | `right` |
| 4 | 0.000 | 0.000 | 终点 |

`left` 的 Q 值也是正数，因为向左后仍可能在后续动作中改为向右并最终到达目标。但每个非终点位置的 `right` 都更高，所以当前学到的最佳动作是向右。

关闭探索并停止更新后，评估 10 个 episode：

```text
到达目标: 10/10
平均步数: 4.00
平均总奖励: +0.97
```

这说明在当前固定环境和参数下，Q 表学到的利用策略会连续执行 4 次 `right`。训练期间的 497/500 和评估时的 10/10 不矛盾：训练时仍有 20% 概率随机探索，评估时已经关闭探索。

> [!success] 当前证据
> 纯 Python 玩具环境的训练循环实际运行成功，18 项单元测试通过；这不是 Gymnasium、Isaac Lab、仿真机器人或真机验证。

## 本课尚未做的事

本课只在一个固定的五格环境中运行一次训练设置，还没有比较不同参数，也没有使用独立环境或机器人。因此，它只能确认完整 Q-learning 循环可以在这个玩具环境中学习。

## 思考题

以下问题都基于本课的五格环境和上面的训练流程：

1. Q 表应该在整个训练开始时创建一次，还是每个 episode 开始时重新创建？为什么？
2. 策略执行动作以前，能不能先更新 Q 值？为什么？
3. 训练时保留探索并更新 Q 表；评估时为什么要关闭探索并停止更新？
4. 一次 step 结束后，哪些数据来自环境，哪些 Q 值会被读取，最终只修改哪个格子？

## 第一次回答记录

1. Q 表只在整个训练开始时创建一次。正确；否则每轮清零会丢失此前经验。
2. 动作执行前不能更新，因为还没有得到环境返回的奖励、新观察和结束状态。正确。
3. 评估时关闭探索并停止更新，是为了观察已经学到的 Q 表能否稳定选择最佳动作，而不混入随机探索或继续学习造成的变化。回答方向正确。
4. 已认识到当前观察是位置 2，并需要关注 `Q(位置2,right)`；但还需要完整区分环境数据与 Q 表读写范围。

> [!example] 第 4 题完整拆解
> - 当前观察 `位置2` 来自本轮开始的 `reset()` 或上一个 step；
> - 动作 `right` 由策略根据当前 Q 表和 ε-greedy 选择；
> - 执行动作后，环境返回新观察 `位置3`、奖励 `-0.01` 和 `done=False`；
> - 更新时读取旧值 `Q(位置2,right)=0.30`，还读取位置 3 整行 `[0.20, 0.80]` 并取最高值 `0.80`；
> - 最终只写回 `Q(位置2,right)`，位置 3 的两个 Q 值都不修改。

## 订正回答

在新场景中，策略选择 `right`；环境返回新观察 `位置2`、奖励 `-0.01` 和 `done=False`。更新时读取 `Q(位置1,right)` 和位置 2 的所有 Q 值，最终只修改 `Q(位置1,right)`。回答正确。

> [!success] 本课结论
> Q 表跨 episode 保留；每个 step 必须先由策略选择动作、再取得环境结果，随后读取当前格子与下一行，并只更新当前观察和动作对应的格子。
